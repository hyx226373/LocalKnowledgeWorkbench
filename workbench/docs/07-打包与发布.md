# 07 打包、数据目录与发布加固（第八轮：Windows 真机反馈）

## 1. Windows 打包
- `npm run dist:win` → `scripts/dist-win.mjs nsis portable`：先 `npm run build`，再 `electron-builder --win nsis portable --x64`。产物在 `release/`：
  - `LocalKnowledgeWorkbench-<版本>-win-x64-setup.exe`（NSIS 安装包）
  - `LocalKnowledgeWorkbench-<版本>-win-x64-portable.exe`（免安装，单文件）
  - `win-unpacked/`（未打包目录，可直接运行，供冒烟测试）
- NSIS 配置（`package.json` `build.nsis`）：`oneClick:false`、`perMachine:false`（装到当前用户，不需要管理员）、`allowToChangeInstallationDirectory:true`、桌面与开始菜单快捷方式（名称「本地知识工作台」，`shortcutName`）、`uninstallDisplayName`、`deleteAppDataOnUninstall:false`。
- 卸载询问是否删除用户数据：`build/installer.nsh` 的 `customUnInstall` 宏弹出“是/否”，**默认“否”（保留）**；静默卸载（`/S`）和升级覆盖安装（`${isUpdated}`）都保留。选“是”时删除 `%LOCALAPPDATA%\LocalKnowledgeWorkbench` 与旧的 `%APPDATA%\LocalKnowledgeWorkbench`。用户注册的根目录中的文件从不删除。
- 签名：发布构建通过 `CSC_LINK`/`CSC_KEY_PASSWORD` 签名。本地无证书构建设 `KB_WIN_UNSIGNED=1` → `-c.win.signExecutable=false`：只跳过签名，图标、版本信息与 asar 完整性资源仍写入 exe。
- 图标：`build/icon.ico`（16–256 px）与 `build/icon.png` 是**占位图标**，由 `npm run icon`（`scripts/gen-icon.py`）生成；正式图标替换同名文件即可。
- 在 Linux 上交叉打包：NSIS 需要 wine（electron-builder 用它生成卸载程序），本盒子已 `apt install wine wine64`；portable/zip 不需要 wine。改写 exe 资源（图标、版本信息）在 electron-builder 26 中不需要 wine。

## 2. 用户数据目录
- Windows：`%LOCALAPPDATA%\LocalKnowledgeWorkbench`（`src/main/userDataDir.ts`，在 `app.ready` 之前 `app.setPath('userData'|'sessionData')`）。理由：元数据库、索引、网页会话、缓存都是本机数据，不应进入漫游配置（域环境下会随登录同步，体积大且可能冲突）。
- 一次性迁移：旧版本使用 Electron 默认的 `%APPDATA%\LocalKnowledgeWorkbench`（Roaming）。启动时若旧目录有 `workbench.db`、新目录还没有，就整体搬过去：先 `rename`（同盘瞬间完成），失败则复制并在旧目录留下说明文件（旧数据不删除）。新目录已有数据时不覆盖。结果写到主进程日志 `[userData] …`。
- `KB_USER_DATA=<目录>` 优先（测试、便携），不迁移。Linux/macOS 保持 Electron 默认位置。
- productName 仍是 `LocalKnowledgeWorkbench`（目录名、exe 名不含中文，避免路径编码问题）；界面显示名见 §5。

## 3. 首次启动不被授权框挡住
- 真机反馈针对旧版 8e792ef：内置示例插件 `demo.csv-table` 当时按 `source:'user'` 加载，启动时就弹字符串权限确认框。第四轮起它与内置阅读器一样是 `source:'builtin'`，在渲染进程运行、**不请求授权**；字符串权限确认流程已删除。
- 现在只有第三方沙箱适配器会询问，而且只在**用户打开（或工作区中显示）需要该权限的内容时**询问（`SandboxPanel` 的授权门，docs/06 §4）。
- e2e（`e2e/e2e.mjs`）：全新数据目录首次启动、以及恢复含 CSV/PDF/Markdown 面板的工作区重启后，再等 2 秒，界面上没有任何对话框。

## 4. 冷启动
- 计时：`src/main/startupTrace.ts`。主进程与渲染进程（`kb:startup-mark`）的阶段都换算成“距进程启动的毫秒数”。开发运行（未打包）或 `KB_STARTUP_TRACE=1` 时在主进程日志打印一张表；每次启动都写 `<数据目录>/startup-trace.json`（真机反馈时可直接附上）。`kb.getStartupTrace()` 供 e2e 读取。
- 阶段：`main:module-start` → `app:ready` → `main:service-open`（打开 SQLite）→ `window:created`/`window:shown` → `renderer:first-paint` → `renderer:modules-evaluated` → `renderer:themes-listed` → `renderer:plugins-loaded` → `renderer:first-contentful-paint` → `renderer:interactive`（工作区布局恢复后的第二帧）→ `deferred:start-*` → `deferred:scans-done`。
- 延后的非关键任务（`startDeferred`）：启动对账扫描（worker）、chokidar 监听（首次遍历在主进程）、清理暂存区、清理过期网站数据。渲染进程报告可交互后开始；没有报告时最迟窗口创建后 5 秒开始。
- 内置插件与主题包仍在首屏前加载：恢复的面板需要它们的适配器；第三方沙箱插件只登记声明，代码在面板显示时才在 iframe 中加载。
- 窗口创建时立即显示（深色背景色，不等 `ready-to-show`），所以“窗口显示”≈ 窗口创建。
- 测量：`xvfb-run node scripts/measure-startup.mjs 5 --label <标签>`（生产构建、直接启动 electron、不经 Playwright；根目录 20 000 个文件，其中一半在 `node_modules`/`.git`；工作区恢复 PDF + Markdown + CSV 三个面板；第 1 次预热不计，取 5 次中位数）。结果在 `verify/startup-before.json` / `verify/startup-after.json`。

| 阶段（Linux 盒子，xvfb，软件渲染，中位数 ms） | 改动前 | 改动后 |
| --- | --- | --- |
| 窗口显示 `window:shown` | 176 | 164 |
| 首次绘制 `renderer:first-paint` | 338（259–703） | 226 |
| 主题包列出 `renderer:themes-listed` | 549 | 277 |
| 插件加载完 `renderer:plugins-loaded` | 727 | 284 |
| 首次内容绘制 `renderer:first-contentful-paint` | 959 | 538 |
| **可交互 `renderer:interactive`** | **1072** | **636** |
| 对账扫描完成 `deferred:scans-done` | （与首屏并行） | 1201 |

改动前，chokidar 对 2 万个文件的首次遍历与启动扫描和首屏抢主进程，渲染进程的 IPC（读布局、列主题包、登记插件）都要排队。目标“窗口显示 < 1.5 s、可交互 < 3 s”在 Linux 上满足；Windows 真机（杀毒软件扫描、机械硬盘）未测，请用 `startup-trace.json` 反馈。

## 5. 目录树的忽略规则
- 目录树（`WorkbenchService.listDir`）、索引扫描、文件监听共用 `isIgnoredName`（`DEFAULT_IGNORES`：`.git`、`node_modules`、`$RECYCLE.BIN`、`System Volume Information`、`.DS_Store`、`Thumbs.db`、`desktop.ini`）。真机反馈：旧版目录树会列出 node_modules 等，展开时卡顿。
- 设置“显示被忽略的项”（目录树标题旁的复选框；保存在 `settings.showIgnored`）：打开后被忽略的项以淡色斜体显示（`ignored: true`），可以浏览和打开，但仍不进入索引与搜索。其他点文件（如 `.notes.md`）不在忽略列表中，照常显示和索引。

## 6. 中文菜单与显示名
- `src/main/appMenu.ts` 替换 Electron 默认英文菜单：文件（插件管理、安装主题包、退出）、编辑（撤销/重做/剪切/复制/粘贴/全选）、视图（命令面板 Ctrl+Shift+P、关闭所有标签、全屏；开发运行时另有重新载入/开发者工具）、帮助（关于：版本与数据目录）。菜单栏默认隐藏（`autoHideMenuBar`，按 Alt 显示），工作台命令经 `kb:menu-command` 交给渲染进程的命令注册表执行；快捷键仍由渲染进程处理（菜单只显示）。
- 显示名：窗口标题、关于、快捷方式（`nsis.shortcutName`）、“应用和功能”中的卸载名（`uninstallDisplayName`）都是「本地知识工作台」；`productName` 仍是 `LocalKnowledgeWorkbench`（安装目录、exe 名、数据目录，避免非 ASCII 路径问题）。Windows 上 `app.setAppUserModelId('local.kb.workbench')` 与 `appId` 一致（任务栏分组、固定到任务栏）。
- 文件说明：exe 的 FileDescription（资源管理器「文件说明」、任务管理器显示名）经 `build.afterSign` → `scripts/afterSign-file-description.mjs` 写为「本地知识工作台」；`productName` / 安装目录 / artifact 文件名仍为英文 `LocalKnowledgeWorkbench`（electron-builder 默认把 FileDescription 写成 productName，故必须在 afterSign 覆盖）。

## 7. Electron fuses（正式构建）

`package.json` → `build.electronFuses`，electron-builder 在打包时（afterPack 之后、签名之前）写入可执行文件，所以 `dist:win` / `dist:win-portable` / `dist:linux-dir` 的产物都带 fuses：

| fuse | 值 | 说明 |
|---|---|---|
| RunAsNode | 关 | `ELECTRON_RUN_AS_NODE=1 产物.exe` 不再是一个 Node 解释器 |
| EnableNodeOptionsEnvironmentVariable | 关 | 忽略 `NODE_OPTIONS`（例如 `--require` 注入） |
| EnableNodeCliInspectArguments | 关 | 忽略 `--inspect` / `--inspect-brk` |
| EnableCookieEncryption | 开 | cookie 用系统钥匙串加密（Windows 上为 DPAPI）；网页面板的登录态受保护 |
| EnableEmbeddedAsarIntegrityValidation | 开 | 校验 app.asar 头部哈希（Windows/macOS 生效；Linux 上 Electron 不支持，此项无效果） |
| OnlyLoadAppFromAsar | 开 | 只从 app.asar 加载应用代码，不读同目录的 `app/` 文件夹 |
| LoadBrowserProcessSpecificV8Snapshot | 关（默认） | 未使用 |
| GrantFileProtocolExtraPrivileges | **保持开（默认）** | 渲染进程通过 `loadFile` 走 file://，pdf.js worker 等依赖 file:// 的额外权限；改用自定义协议前不关 |

不受影响的部分：

- 单元测试（`scripts/run-electron-node.mjs` 用 `ELECTRON_RUN_AS_NODE` 跑 node_modules 里的开发版 Electron）和所有 e2e（Playwright 启动未打包的 `electron .`）都**不用打包产物**，所以照常运行。
- worker 线程、utilityProcess 不依赖 RunAsNode，打包产物内照常可用（冒烟第 1 项验证了扫描完成）。

验证：`npm run dist:linux-dir && npm run smoke:packaged`（Linux 无显示时加 `xvfb-run -a`），或指定产物：`node e2e/packaged-fuses-smoke.mjs release/win-unpacked/LocalKnowledgeWorkbench.exe`（在 Windows 上）。冒烟不用 Playwright（fuses 打开后 Playwright 无法注入），而是直接启动进程并读 `<数据目录>/startup-trace.json`：

1. 正常启动 → trace 有 `renderer:interactive` 与 `deferred:scans-done`（数据目录预先由开发构建注册一个根）
2. `ELECTRON_RUN_AS_NODE=1 产物 -e "写文件"` → 文件未写、应用正常启动
3. `NODE_OPTIONS=--require 恶意脚本` → 脚本未执行
4. `--inspect=9339` → 端口无监听
5. `@electron/fuses read` 读数与配置一致

只读 fuses：`npx @electron/fuses read --app release/win-unpacked/LocalKnowledgeWorkbench.exe`。
旧的 `e2e/packaged-smoke.mjs`（Playwright）只适用于 `-c.electronFuses=null` 构建的产物。

## 8. 外观切换时 Markdown 阅读位置按锚点保持

`useScrollState`（`src/renderer/plugins/builtin-readers/index.tsx`）记录**阅读锚点**：视口顶边所在的正文块（`article` 的直接子元素）以及顶边在块内的比例。以下情况把同一块的同一位置放回视口顶部，而不是保持 `scrollTop` 像素值或滚动比例：

- 正文或滚动容器尺寸变化（ResizeObserver：字号、行高、内边距、栏宽、外框顶栏/标签高度变化）；
- 外观切换：`applyAppearance` 在 window 上派发 `kb:appearance-changed`，阅读器在下一帧校正一次（覆盖正文总高度不变、但锚点上方块尺寸变化的情况）。

校正后的 `scrollTop` 会触发一次上报，工作区里保存的是新排版下等价的滚动比例。验收（`e2e/e2e-workspaces.mjs`）：在文章开头插入固定高度块（不随字号缩放，使“按比例”与“按锚点”结果不同），滚到某段中间，切到 study 外框 + bright 阅读区（字号 13→15px、行高、顶栏高度都变）→ 同一块、块内比例差 ≤ 0.05，`scrollTop` 7880→10455、比例 0.663→0.615（不是按像素/比例）；切回 → 像素值回到原值 ±2；正文总高度不变的外观变化 → 仍为同一块。


## 索引子进程（r11-E）

打包态 `electronFuses.runAsNode=false`，禁止 `child_process.fork`。`@kb/indexer` 通过可注入的 `setIndexerFork`，由应用 `src/main/indexerHost.ts` 在 `import('@kb/indexer')` 之前注入 `utilityProcess.fork`。

- **asar**：`utilityProcess.fork` 可加载 asar 内 `@kb/indexer/dist/worker.js` / `read-helper.js`。
- **asarUnpack**：`better-sqlite3/**` 与 `@kb/indexer/dist/**`（原生模块与 worker 旁路缓存）。
- **开发态**：默认仍 `child_process.fork`；`KB_FORCE_UTILITY_INDEXER=1` 可强制演练。
- **禁止**：把 `runAsNode` 改回 true。
