## 1. dockview 能力核对（dockview / dockview-core 8.4.0）

当前依赖已是 npm 最新版 **8.4.0**（2026-09-30 发布），**本轮不升级**，也没有可升级的版本。所有结论按 8.4.0 源码（`node_modules/dockview-core/dist/dockview-core.js`）与实测核对。

| 需求 | dockview 8.4 | 结论 | 补齐方案（本分支） |
|---|---|---|---|
| 面板上下左右移动 | 浮动组 `addFloatingGroup`；`floatingGroupDragHandle:'tabbar'`：拖**标签栏右侧空白处**移动（不再渲染单独的空白标题栏 `.dv-floating-titlebar`） | **原生** | `pm.move()`；`floatingGroupBounds:{minimumWidthWithinViewport:40, minimumHeightWithinViewport:40}`：允许部分移出，标签栏左上至少 40×40 留在可见区域；超出 dock 区域的部分被裁掉（`.dv-floating-overlay-host{overflow:hidden}`） |
| 独立调整宽、高 | 浮动组 8 个缩放把手；分屏用分隔条 | **原生** | `pm.resize()`：浮动改矩形，分屏改分组尺寸。注：dockview 以**第一次 pointermove** 作为缩放起点，第一步的位移会让窗口平移同样的像素（真实鼠标通常 1–2px，e2e 里先挪 1px 规避） |
| 层级 z-order / 带到最上层 | 全局 aria-level 计数，激活组即置顶；`overlay.bringToFront()` | **部分**：有层级，但 `toJSON` 只按创建顺序保存浮动组，**不保存层级** | 本层保存 `windows.order`（从下到上），`restoreLayout` 依次 bringToFront |
| 收起成气泡 | 无（边缘组 edge groups 只能收进四边，不是气泡） | **缺失** | 本层实现：窗口打 `data-pm-collapsed` → `visibility:hidden`（不用 display:none，阅读器在隐藏时仍可恢复滚动；子元素同样强制隐藏、不接收指针——dockview 给当前标签的关闭按钮设了 `visibility:visible`，否则会从收起窗口里漏出孤立的「×」）；气泡栏 `BubbleTray`（状态栏上方）；分屏面板收起时移入隐藏浮动窗口，恢复时停回原邻居旁 |
| 最大化 / 还原（分屏） | `api.maximizeGroup / exitMaximizedGroup` | **原生**（只对 grid 分组），状态不进 toJSON | 直接使用；本层保存 `windows.gridMaximized`，重启后再最大化 |
| 最大化 / 还原（浮动窗口） | `group.api.maximize()` 对浮动组无效 | **缺失** | 本层：记住原矩形（`floats[id].maximized.restore`），setBounds 到整个 dock 区域并置顶；还原回原矩形 |
| 停靠 ↔ 浮动切换 | `addFloatingGroup(panel)`；拖标签进分屏边缘停靠（原生 DnD） | **原生** | `pm.float / dock / toggleFloat`；标题栏按钮（⇱ 浮动 / ⇲ 停靠） |
| 拖拽吸附到分屏 | 拖标签到分组边缘/中心的 drop target | **原生** | 保留，不改 |
| 浮动窗口之间/贴边吸附 | Smart Guides（`smartGuides`）**属于 dockview-enterprise**：社区版设置会报错 `requires the "SmartGuides" module` | **缺失（社区版）→ 自研** | 用社区版公开的 `transformFloatingGroupDrag` 在**拖动过程中**吸附：每一步对建议位置做 `snapBox`（8px，四条边，贴容器边和其他浮动窗口的边），再做 `keepGrabbable`；API `move` 同样吸附。无参考线 |
| 侧栏纳入同一机制 | 侧栏不是 dockview 面板 | **缺失** | 侧栏浮动时变成一个 dockview 浮动面板（id/组件 `kb.sidebar`，锁定不可放入其他标签），内容用 React portal 渲染**同一个** `<Sidebar>`；浮动时“侧栏”只在标签上显示一次（内部标题条只在停靠时显示）；停靠时仍是原 `<aside>`（原分栏宽度不变） |
| Popout（独立系统窗口） | `addPopoutGroup` 需要 `window.open` 同源 popout.html | **原生但被禁用**：主进程 `setWindowOpenHandler(() => ({action:'deny'}))` | 本轮不启用，待产品决定（§10） |
| 序列化 toJSON / fromJSON | 包含 grid、floatingGroups（位置）、popoutGroups、edgeGroups | **部分**：无层级、无最大化、无收起 | dock JSON 照旧放 `layout.dock`，本层状态放 `layout.windows`（自带版本号，§4） |
| 屏幕变化找回 | 容器 layout 时 `constrainBounds` **只平移不缩小** | **部分** | 本层 `rescueBox`：先缩到容器内（不小于 240×140），再平移；ResizeObserver + window resize + restoreLayout 时触发 |
| 网页面板（原生 WebContentsView）与浮动叠放 | 无（原生视图永远画在 DOM 之上） | **缺失** | 本层注册遮挡探针：层级更高的浮动窗口与网页相交 → 网页显示截图（§5） |
| 撤销/重做、`onWillMutateLayout` 等 | 有 | 原生 | 本层用 `onWillMutateLayout/onDidMutateLayout` 在结构变化前后快照/写回所有面板的滚动位置（dockview 重挂载内容 DOM 时浏览器会静默清零）。宽度没变按原像素写回，宽度变了（重排）按“视口顶部在全文中的比例”换算；写回在两帧后执行并在 120/400ms 校正，期间再发生结构变化以正在写回的值为准 |

内部接口：`DockviewApi` 没有公开浮动窗口对象，本层通过 `dockviewBridge.ts` 访问 component 上的公开 getter
`floatingGroups / getFloatingWindowForGroup / getFloatingContainer`，启动时做运行时校验（`VERIFIED_DOCKVIEW='8.4.0'`），
升级 dockview 后若接口变化会给出明确错误，只需改这一个文件。

**升级结论**：不需要也不能升级（已最新）。Smart Guides 若想用原生实现需要购买 dockview-enterprise（许可与成本待决定），本层用 `transformFloatingGroupDrag` 做的拖动中吸附已覆盖“贴边/贴窗”（没有参考线）。

## 2. 统一面板管理层架构

```
src/renderer/panel-manager/
  types.ts           数据模型、PanelManagerApi、版本号 PANEL_LAYOUT_VERSION=1
  geometry.ts        纯函数：rescueBox / snapBox / maximizedBox / cascadeBox / normBox（单测覆盖）
  serialize.ts       windows 字段的默认值、迁移、净化、大小上限（64KB）
  dockviewBridge.ts  dockview 内部接口的唯一出口 + 版本校验
  webOcclusion.ts    网页面板遮挡判断（层级更高的浮动窗口）
  PanelManager.ts    实现（单例 instance.ts → panelManager）
  react.tsx          WindowButtons / PanelHeaderActions / SidebarSlot / SidebarPanel / BubbleTray
  viewContract.ts    插件视图窗口能力声明（草案，§7）
  panel-manager.css  只用 --kb-* 令牌；.kb-dock{isolation:isolate} 让浮动窗口始终在菜单/对话框之下
```

- “窗口” = 文档/网页面板（id = itemId）或侧栏（`kb.sidebar`）。每个窗口 mode ∈ docked | floating | collapsed。
- App 只在 onReady 里 `panelManager.attach(api)`，保存时 `dockForSave(api.toJSON())` + `windows: serialize()`，加载时 fromJSON 后 `restoreLayout(windows)`。
- 新打开的面板若落进侧栏窗口或隐藏窗口，会被移到最近的分屏分组（`relocateIfMisplaced`）。

## 3. API（`window.__kb.pm` 同一实例，e2e 也用）

| 方法 | 说明 |
|---|---|
| `list() / get(id)` | `WindowInfo {id,title,kind,mode,bounds(容器坐标),z,maximized,groupId}` |
| `move(id,{left,top})` | 停靠的先浮动；吸附（8px）后按 `keepGrabbable` 夹住：可以部分移出，但顶部不能移出、标签栏左上 40×40 必须可见 |
| `resize(id,{width?,height?})` | 浮动改矩形（不小于 240×140）；停靠改分组尺寸 |
| `bringToFront(id)` | 置顶 |
| `collapseToBubble(id) / restoreFromBubble(id)` | 收起成气泡 / 恢复到原位置（原来在分屏的停回原邻居旁，原来浮动的回原矩形） |
| `maximize(id) / restore(id)` | 浮动：占满 dock 区域；分屏：dockview 原生最大化；侧栏：先浮动再最大化，还原回原状态 |
| `float(id,box?) / dock(id,{ref,direction}?) / toggleFloat(id)` | 停靠 ↔ 浮动 |
| `serialize()` → `PanelLayoutV1` | 当前状态 |
| `dockForSave(json)` | 去掉侧栏浮动面板（不是工作区条目） |
| `restoreLayout(raw)` | 任意版本/缺失 → 迁移后恢复 |
| `rescue()` | 夹回可见区域，返回被移动的窗口数 |
| `stats` | `{rescued, relocated, snapped}`（e2e 统计） |

## 4. 保存格式与迁移

- `layout.schema` **仍为 4**（不动主进程校验）；新增可选字段 `layout.windows`：
  `{ v:1, viewport:{width,height}, order:[id…从下到上], collapsed:{id:CollapsedInfo}, floats:{id:{maximized?}}, gridMaximized?, sidebar:{mode,bounds?,collapsed?,maximized?} }`
- 只含 id、数字和枚举——**不含文件内容、路径、URL、密钥**（e2e 检查）。超过 64KB 时只保留侧栏状态。
- 迁移 `migratePanelLayout`：缺失（旧工作区）→ v0 视为“全部停靠、侧栏停靠”；v1 原样净化；v>1（新版本写的）只读已知字段，不报错。
- 旧版本应用读取新文件：忽略 `windows`，浮动组仍由 dockview JSON 恢复（只是丢失层级/收起/最大化）。
- `src/shared/items.ts` 的 `pruneDock` 现在也裁剪 `floatingGroups/popoutGroups`（删掉不存在的面板与空窗口），导出/导入 `.kblayout.json` 原样带 windows。

## 5. 网页面板与浮动/层级的实际表现（Linux Xvfb 实测）

网页是主进程的原生 `WebContentsView`，总是画在整个渲染进程 DOM **之上**，CSS z-index 对它无效。沿用 docs/06 §11.3 的“遮挡 → 截图”机制，并加了一个探针：

| 场景 | 实际表现 | 截图 |
|---|---|---|
| 网页在分屏，没有遮挡 | 真网页，原生视图与占位重合（偏差 0px） | 01 |
| 浮动 MD 盖在分屏网页上 | 网页区域改显示**最近一帧截图**（不可交互），MD 完整可见、可操作 | 02、04 |
| 网页是浮动窗口但不在最上层，与上层窗口相交 | 同上，显示截图 | 04 |
| 点网页窗口（标签/标题栏）带到最上层 | 同一帧切回真网页，与占位重合（偏差 0px），盖住下面的窗口 | 05 |
| 拖动最上层的网页窗口 | 每一步原生视图跟随（e2e 每步偏差 ≤ 1px；肉眼可能有一帧延迟） | — |
| 工作台菜单/对话框盖在网页上 | 菜单在所有浮动窗口之上（dock 区域独立层叠上下文）；与网页相交时网页显示截图 | 06 |
| 网页收起成气泡 | 原生视图隐藏；恢复后是同一个网页（没有重建、滚动位置还在） | 07、08 |
| 被最大化的浮动窗口盖住 | 截图 | 09 |
| 窗口缩到 1024×700 / 重启 | 原生视图仍跟随占位；重启后地址与滚动位置恢复 | 12、13 |

| 两个网页窗口互相重叠 | 上层的显示真网页，下层的显示截图；点下层窗口带到最上层后两者互换；移开不再重叠后两个都是真网页 | 15、16 |

截图来源：主进程在页面滚动/加载稳定后缓存一帧；还没有缓存时（刚显示就被遮住）当场截一张，空图不覆盖旧截图。
限制：截图状态下网页不能点击/滚动，要先把网页窗口带到最上层；
另外修了一个既有隐患：WebSurface 的“正在拖放标签”标记依赖 dragend，拖放源被移出 DOM 时收不到 dragend 会一直显示截图，现在收到任何指针事件即清除。

## 6. 找回（屏幕尺寸/分辨率变化）

两种夹法：
- `keepGrabbable(box, container)`（用户移动、平时）：left ∈ `[40-宽, 容器宽-40]`，top ∈ `[0, 容器高-40]`，尺寸不小于 240×140——允许部分移出，但标签栏一定能抓到。
- `rescueBox(box, container)`（屏幕变小）：宽高先夹到 `[240×140, 容器尺寸]`，再把 left/top 夹到 `[0, 容器-尺寸]`，完整回到可见区域。

触发：dock 区域 ResizeObserver、window resize（容器比上次小 → `rescueBox`，否则 `keepGrabbable`）、`restoreLayout`（当前容器比保存时的 `viewport` 小 → `rescueBox`）。（最大化的浮动窗口在容器变小后同样被夹回；容器变大后不会自动重新占满，需再点一次最大化——待改进。）
e2e：运行中把窗口缩到 1024×700 → 全部浮动窗口（含侧栏）在可见区域内；在 1500×950 保存后强杀，以 1024×700 启动 → 全部找回（截图 13、14）。

## 7. 推广到所有插件视图（方案与接口草案，本轮只实现校验与默认值）

1. **声明**：适配器（内置 `ReaderAdapter`、沙箱 manifest `contributes.adapters[]`）与侧栏面板扩展点增加可选 `window` 字段，类型 `ViewWindowDecl`（`src/renderer/panel-manager/viewContract.ts`）：

```ts
interface ViewWindowDecl {
  minSize?: { width?: number; height?: number };        // 默认 240×140，范围 80–4096
  defaultFloatSize?: { width?: number; height?: number }; // 首次浮动尺寸，默认容器 55%×60%
  canFloat?: boolean;       // 默认 true
  canDock?: boolean;        // 默认 true；与 canFloat 不能同时为 false
  canCollapse?: boolean;    // 默认 true
  canMaximize?: boolean;    // 默认 true
  initialPlacement?: 'dock' | 'float'; // 默认 'dock'
  nativeSurface?: boolean;  // 原生表面（网页/外部程序）→ 遮挡时显示截图；默认按 displayMode 推断
  canPopout?: boolean;      // 待产品决定，默认 false
}
```
2. **校验**：`resolveViewWindow(decl, displayMode)` 返回默认值补全后的结果和错误列表；manifest 校验走同一函数，错误时拒绝安装（与现有 manifest 校验一致）。
3. **执行**：PanelManager 在 `float/maximize/collapseToBubble` 前查询该面板视图的 resolved 声明，不允许的操作按钮置灰、API 返回 no-op；`minSize` 同时用于浮动窗口最小尺寸与 dockview 分组 `minimumWidth/Height`；`nativeSurface` 的视图自动注册遮挡探针。
4. **SDK**：kb-adapter-sdk 的模板与类型增加 `window` 字段，`stateSchemaVersion` 不受影响；旧插件不声明 = 全部默认值（行为与本轮一致）。
5. **阅读位置**：自由窗口会频繁重挂载 DOM，插件视图应把阅读位置写进视图状态（本轮给 CSV 示例补了 `scroll`）；面板管理层的滚动快照只是兜底。
6. 下一轮工作量估计：适配器注册与 manifest schema 加字段 + 按钮置灰 + 分组最小尺寸 + SDK 模板，约 1–2 天。

## 9. 已知限制

- 浮动窗口不能拖出主窗口变成独立系统窗口（popout 未启用，本轮保持现状）；可以部分移出 dock 区域（至少 40px 标签栏可见），超出部分被裁掉。
- 网页：被遮挡时只显示截图（§5），两个网页重叠时上层真网页、下层截图。
- 拖动中吸附，但没有参考线；缩放不吸附。
- dockview 小毛病：缩放时第一次鼠标移动会被当成平移（dockview 自身行为）；快速拖动标签栏空白处时浏览器可能误启动标签的 HTML5 拖放、把面板停靠进分屏——本层在捕获阶段拦掉从空白处开始的手势里其他元素的 dragstart（按住 Shift 拖空白处停靠仍可用）。
- 依赖 dockview 内部 getter（bridge 有版本校验）。
- 收起全部分屏面板后分屏区为空（显示 watermark），恢复时停回原邻居旁。
- 没有在 Windows / macOS 真机测试（Windows 上 WebContentsView 截图、DPI 缩放下的坐标换算都需要真机确认）。

## 10. 需要产品决定

1. **气泡放在哪里**：当前是状态栏上方的一条“已收起”气泡栏（窗口宽度内横排）。备选：dock 区域右下角悬浮气泡 / 侧栏底部 / 标题栏。
2. **浮动面板能否拖出主窗口成为独立系统窗口**（popout）：dockview 原生支持，但要放开主进程 `setWindowOpenHandler` 的同源 popout 页、处理多窗口的网页视图与保存格式，安全面需评估。
3. **吸附阈值**：当前 8px（容器四边 + 其他浮动窗口的边），拖动中吸附。是否需要参考线（需 dockview-enterprise 或自研）？是否吸附分屏分隔条？
4. 浮动窗口最小尺寸 240×140、允许部分移出（标签栏至少 40px 可见）——第二轮已按产品意见确定。
5. 网页被遮挡时显示截图是否可接受，或改为“网页窗口永远在最上层”。
