### T1 第一个实用的搜索：文件名 + 路径 + 正文 🟡（目前只有文件名/路径）
> 产品决定：第一个实用版本 = 文件名、路径，以及 txt / md / **有文本层的 PDF** 的正文。OCR（扫描版 PDF、图片）以后再做。
- **输入**：现有 `resources` / `resources_fts`、indexWorker；样例根（含中文 txt/md、文本型与扫描型 PDF）。
- **交付物**：worker 中的正文抽取（txt/md 直接读，PDF 用 pdfjs-dist 在 worker 中逐页抽文本）→ `content_fts(resource_id, page, text)`；增量（只处理 size/mtime/hash 变化的文件）；搜索 API 返回片段与页码；搜索结果 UI（文件名命中与正文命中分组、高亮片段）；PDF 阅读器支持 `openAt(page, query)`。
- **依赖**：T2（事件驱动增量）、T3（PDF 跳页）。
- **验收方式**：
  1. 在 1 万文件 / 5 GB 的根上首次索引期间，界面可正常滚动与打开文件，状态栏显示进度并可取消；取消后再次扫描能继续完成。
  2. 搜索中文词“对账扫描”，0.5 秒内出现结果，结果显示所在文件、上下文片段；点击 PDF 结果打开并定位到命中页、命中词高亮。
  3. 在外部编辑器修改某 md 加入新词并保存，5 秒内能搜到；删除该文件后搜不到。
  4. 扫描型（无文本层）PDF 在结果中不报错，文件详情提示“无可搜索文本”。

### T2 文件监听与对账 🟡（基础已完成）
- **输入**：`RootWatchers`（chokidar）、`reconcileScan`、`upsertSeen` 身份规则。
- **交付物**：网络盘/可移动盘检测并切换为轮询或“仅对账”；系统唤醒/根重新上线时自动对账；定时轻量对账；跨根移动识别；忽略规则配置；监听异常在状态栏可见。
- **依赖**：无。
- **验收方式**：
  1. ✅（Linux 已自动化）应用运行时在资源管理器中重命名已收藏且已打开的文件：收藏、标签标题自动更新，标签内容仍可读。
  2. 应用关闭时把收藏文件移动到另一个子目录，再启动：收藏仍指向它（不显示失联）。
  3. 在 SMB 共享上注册根：状态栏如实显示“轮询/仅对账”，外部新增文件在下一次对账后出现。
  4. Windows 上只改大小写重命名（`Note.md → note.md`）：收藏不丢失、不出现重复条目。
  5. 拔掉 U 盘：该根显示“离线”，收藏显示不可用但不被删除；插回后自动恢复。

### T5 操作记录与恢复 🟡（服务层已完成）
- **输入**：`trash/writeText/move/undo/preview*`、`op_log`、`blobs/`、`staging/`。
- **交付物**：文件操作 UI（重命名、移动、删除）及其预览对话框；操作记录面板（按时间/actor 过滤、预览撤销、冲突处理“保留两者/覆盖/取消”）；暂存区占用与保留期设置；Windows 保留名/非法字符校验。
- **依赖**：T6（Agent 操作需在面板中可见）。
- **验收方式**：
  1. 删除一个含 100 个文件的文件夹：预览显示“100 个文件 / 大小 / 将移入应用暂存区，可恢复 30 天”；确认后文件夹从树中消失；在操作记录中点“撤销”后原样回来，收藏仍有效。
  2. Agent 覆盖一个文件后用户又手动编辑；撤销 Agent 操作时提示冲突，选“保留两者”后用户修改与原内容都可找回。
  3. 撤销时原位置已有同名文件：提供“保留两者”，恢复为“名称 (恢复 1)”。
  4. 暂存条目超过保留期被清理后，撤销按钮显示“已无法恢复”，不报未处理错误。
