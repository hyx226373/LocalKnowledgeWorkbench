# 12 数据迁移（第九轮：换电脑 / 换资料路径）

目标：证明用户数据（工作区、阅读位置、收藏、主题选择、插件状态）能导出成一个包，在**另一台电脑或另一套路径**上导入，把根目录映射到新位置后原工作区原样打开；导入前自动备份，失败自动恢复。

代码：`src/main/migration/`（不依赖 Electron 的部分可直接在测试中调用）

| 文件 | 作用 |
|---|---|
| `format.ts` | 包格式常量、manifest 类型、导出白名单、密钥样键规则、路径风格判断 |
| `zip.ts` | 最小 zip 读写（无新依赖；UTF-8 文件名、CRC 校验、拒绝越界条目名/加密/zip64、解压大小上限） |
| `snapshot.ts` | `VACUUM INTO` 一致快照、`integrity_check`、单事务整表替换（ATTACH + defer_foreign_keys + foreign_key_check）、FTS 重建 |
| `exporter.ts` | `exportPackage(svc, file)` |
| `importer.ts` | `loadPackage`、`suggestMappings`、`validateMappings`、`importPackage`、`createBackup` / `listBackups` / `restoreBackup` |
| `repair.ts` | `rootStatuses`、`listMissing`、`relocateResource`（缺失文件重新定位，UUID 不变） |
| `electron.ts`、`ui.ts`、`preload.ts` | 迁移窗口与 `kb-migration` IPC（只接受迁移窗口的调用） |

入口：应用菜单「文件 → 导出数据迁移包… / 导入数据迁移包… / 根目录与缺失文件…」（菜单栏默认隐藏，按 Alt 显示）。

## 1. 用户数据在哪里

数据目录：Windows `%LOCALAPPDATA%\LocalKnowledgeWorkbench`（docs/07 §2），Linux `~/.config/LocalKnowledgeWorkbench`，`KB_USER_DATA` 优先。

| 数据 | 位置 | 是否导出 |
|---|---|---|
| 根目录（逻辑根：id、名称） | `roots` | 是 |
| 根目录在本机的路径 | `root_mounts`（机器本地） | **否**（原路径只写进 manifest 供导入界面显示；导入时按映射重新生成） |
| 资源（稳定 UUID + `root_id` + 相对路径） | `resources` | 是；`file_key`（卷序列号:文件索引 / dev:ino）清空，见 §3 |
| 文件名/路径全文索引 | `resources_fts`（FTS5） | 否（导入时按 `resources` 重建） |
| 收藏 | `favorites`（引用 resource_id） | 是 |
| 命名工作区：标签页、分屏、尺寸、侧栏宽度 | `workspaces.layout_json`（schema 4） | 是 |
| 每个面板的条目与阅读状态（PDF 页码/缩放、Markdown 锚点、插件视图状态） | `workspace_items.state_json` | 是 |
| 当前工作区、外观（主题选择）、目录树展开、设置、窗口尺寸 | `layout` 表：`workspace.current`、`ui`、`settings.*`、`window` | 是（`web.lastUsed.*`、`agent.*`、`migration.*` 与键名像密钥的除外） |
| 已安装主题包 | `<数据目录>/themes/<id>/` | 是 |
| 插件已安装列表、启用状态、授权（按根 id + declHash） | `plugins` | 是 |
| 插件存储 | `plugin_kv` | 是（键名像密钥的除外，见 §4） |
| 第三方适配器插件包 | `<数据目录>/plugins/<id>/` | 是 |
| 虚拟集合 | `collections` / `collection_items`（docs/03 中规划，**80d191e 上尚不存在**） | 表存在时自动导出（白名单已包含），当前 manifest 中 `contents.collections = null` |
| 操作记录、内容备份库、暂存区 | `op_log`、`blobs` 表与 `blobs/`、`staging/` | 否（本机的撤销历史） |
| 插件审计记录、索引状态 | `plugin_audit`、`index_state` | 否 |
| 网页面板网站数据（cookie、登录、缓存） | Chromium 分区 `Partitions/kbweb.*` | 否 |
| 启动计时 | `startup-trace.json` | 否 |
| 原始资料文件 | 用户的根目录 | **否**（默认、也是目前唯一的行为） |

## 2. 迁移包格式（`kb-workbench.migration` v1）

文件名建议 `*.kbmigrate.zip`，普通 zip（可以用任何解压工具查看）：

```
manifest.json            清单（下表）
README.txt               给人看的说明
db/workbench.db          元数据库一致快照（已去掉 §1 中“否”的数据，并 VACUUM）
themes/<id>/…            已安装主题包
plugins/<id>/…           第三方适配器插件包
```

`manifest.json` 主要字段：

| 字段 | 说明 |
|---|---|
| `format` / `formatVersion` | `"kb-workbench.migration"` / `1`。导入端拒绝更高的 formatVersion（提示升级应用） |
| `dbSchemaVersion` | 快照的 `PRAGMA user_version`（当前 5）。比导入端新 → 拒绝；比导入端旧 → 在暂存副本上执行 `db.ts` 的迁移后再导入 |
| `exportedAt`、`app`、`source.platform/pathStyle` | 来源信息 |
| `roots[]` | `id`、`name`、`sourcePath`（原路径，仅显示/建议）、`sourcePathStyle`（`win32`/`posix`）、`resourceCount`、`fileCount`、`referencedCount` |
| `contents` | 工作区数、条目数、当前工作区 id、收藏数、集合数（或 null）、资源数、插件列表（版本/来源/启用/授权数/存储键数）、主题包、外观、layout 键 |
| `excluded` | 未导出的表、layout 键、密钥样插件存储键（只记插件与键名，不记值）、说明 |
| `secrets` | 密钥与令牌的处理说明（§4） |
| `snapshot` | `{ method: "vacuum-into", integrityCheck: "ok" }` |
| `files[]` | 包内每个文件的 `path`、`size`、`sha256`；导入时逐个校验，清单外的 `db/`、`themes/`、`plugins/` 文件一律拒绝 |

包**没有加密、没有签名**（见 §10 产品决定）。

## 3. 一致快照

- 导出前让主窗口把防抖中的布局写完（复用关闭窗口时的 `kb:before-quit` → `kb:flush-done`）。
- 用 `VACUUM INTO '<临时文件>'` 生成快照：单条语句、一个读事务，WAL 模式下索引 worker 等其他连接同时写入也只会看到某一时刻的完整状态；**不复制**正在写的 `workbench.db` / `-wal`。
- 快照先 `integrity_check`，在快照副本上清理（删除不导出的表行、密钥样键，`file_key` 置空），再 `VACUUM`（删除的数据不残留在空闲页），再次 `integrity_check`，结果写入 manifest。
- `file_key` 清空的原因：它在新电脑上没有意义，而且索引器会用“同 file_key 且旧路径已不存在”判断重命名，带过去可能把另一个文件误认成原资源。
- 测试（`tests/migration.test.ts`「写入并发进行时导出」）：3 万条资源撑大库，另一个 worker 线程用独立连接不停地成对写入（一个事务两行），同时连续导出 6 次：每个包的快照 `integrity_check = ok`，成对的两组行数相等（事务一致），且每次导出期间另一连接都完成了数万个写事务（本机一次运行：16660、19890、23707、32077、37789、51793）。

## 4. 密钥与令牌

- 导出白名单之外的表一律不导出（将来新增的表默认不出包，除非加入 `EXPORT_TABLES`）。
- `layout` 中 `agent.*`、`web.lastUsed.*`、`migration.*` 以及键名匹配 `pass|secret|token|api_key|credential|cookie|auth|session` 的项不导出；`plugin_kv` 中键名匹配同一规则的项不导出（manifest 只记插件 id 与键名）。插件把令牌存在普通键名下的情况无法识别（见 §10）。
- **Agent 令牌**：80d191e 没有 Agent 接口，也没有任何 Agent 令牌。规则：将来的 Agent 令牌放在独立的表或 `agent.*` 键中，不在导出白名单内，**不会导出**；新电脑上必须重新生成（旧电脑上的令牌不受影响，需要时在旧电脑上撤销）。
- 插件 `kbfile://plugin/<令牌>` 只在内存中，进程退出即失效；导入/恢复时清空当前进程中的令牌与未执行的批量计划。
- 网页面板的 cookie/登录状态不导出（正式构建用 DPAPI 加密 cookie，本来也不能在另一台电脑上解密）。

## 5. 导入与根目录重映射

流程（`importPackage`）：

1. `loadPackage`：zip 校验 → manifest 格式/版本 → 每个文件 sha256 → 根 id 合法。
2. `validateMappings`：每个根映射到本机的**绝对路径**文件夹，或留空（暂不映射）。拒绝：不存在、相对路径、与数据目录重叠、多个根彼此重叠。此时还没有改任何数据。
3. 暂存：解出数据库，`integrity_check`，旧版本包在暂存副本上执行数据库迁移；解出主题包与插件包。
4. **自动备份**当前数据（§6）。备份失败则不导入。
5. 单个 IMMEDIATE 事务内：用快照替换 `roots/resources/favorites/layout/workspaces/workspace_items/plugins/plugin_kv`（以及存在时的 `collections/collection_items`），`root_mounts` 按映射重写，`index_state` 清空，已映射根下的资源 `missing_since` 置空（交给扫描判断），未映射根下的资源标记缺失（记录保留），重建 FTS，`foreign_key_check` 不通过则回滚。本机的 `web.lastUsed.*` 等机器本地键保留。
6. 替换 `themes/`、`plugins/` 文件夹，重置插件宿主内存状态。
7. 扫描已映射的根（资源按相对路径匹配，UUID 不变；找不到的标记缺失）。
8. 返回：备份位置、已映射/未映射的根、写入行数、当前工作区、缺失数（被引用的 / 总数）。

界面：迁移窗口「导入并映射根目录」页列出每个根（名称、文件数、被引用数、原路径），每行一个新路径输入框 + 「浏览…」+「暂不映射」；可填一个上级文件夹「自动匹配」（按原路径最后一段或根名称，Windows 风格原路径也能取到最后一段）。导入时主窗口先离开工作台页面（不会再写入旧布局），完成后重新载入，直接打开导入的当前工作区。

导入是**替换**，不是合并（见 §10）。

## 6. 回退

- 备份：`<数据目录>/migration-backups/<时间>-before-import/`，内含 `workbench.db`（`VACUUM INTO`，全部表，含 root_mounts 与操作记录）、`themes/`、`plugins/`、`backup.json`。保留最近 5 份。
- 导入在写入元数据之后的任何一步失败（替换文件夹、扫描、模拟失败）→ 自动 `restoreBackup`：单事务整表回写所有表 + 换回两个文件夹，错误信息中注明“已恢复到导入前的数据”和备份位置。写入元数据之前失败（校验、映射、暂存）不改动任何数据。
- 导入成功后也可以在「备份与回退」页手动恢复到导入前。
- **立即备份**（第 9 轮接线）：「备份与回退」页有「立即备份」按钮，菜单「文件 → 备份与回退（立即备份）…」可打开这一页。备份放在 `<时间>-manual/`，内容与导入前备份相同。手动备份和导入前备份**一共保留最近 5 份**（超出时删掉最旧的）。
- 测试：在 after-db / after-files / after-scan 三个点注入失败，恢复后的元数据（roots+mounts、resources、favorites、workspaces、items、layout、plugins、plugin_kv、op_log、FTS 行数）与主题包/插件包目录与导入前**完全相同**；暂存目录被清理。

## 7. 缺失的文件

- 记录从不因为“找不到”而删除：导入不删除任何资源；扫描把找不到的资源标记 `missing_since`。
- 修改了 `indexer.purgeMissing`：原来只保护被收藏的缺失资源，30 天后会删掉只被工作区引用的缺失资源。现在被任何工作区条目引用的也保留，**只被工作区资料（集合，layout `workspace.refs:*`）引用的也保留**（第 9 轮接线，`src/main/service/workspaceRefs.ts`）。
- 资料引用（集合）也计入缺失文件：导入报告里的“被引用的缺失文件”数、迁移窗口的缺失列表（多一列“资料”，写明被哪些工作区的资料引用）、每个根的被引用数都算上资料引用。重新定位时如果合并了重复记录，资料引用也会跟着改指向；失效的资料引用不会被自动清理。
- 显示：工作区面板为“文件不可用”占位（布局、条目与阅读状态原样保留）；侧栏收藏为禁用样式；迁移窗口「根目录与缺失文件」列出每个缺失文件（缺失 · 收藏 · 哪些工作区引用）与每个根的状态（在线 / 离线 / 未映射）。
- 修复：「重新定位」把资源指到某个已映射根内的新文件（`relocateResource`，UUID 不变；若扫描已为新位置建了另一条记录，把那条上的收藏/工作区引用合并过来再删除重复记录），面板自动恢复，PDF 页码等阅读状态仍是原来的；或「重新映射」整个根（`remapRoot` + 扫描）。文件夹不支持单独重新定位（请重新映射根）。

## 8. 结果 (a)：安装包便携性（Windows，**未在 Windows 上实测**）

依据代码（`src/main/userDataDir.ts`、`package.json` build 配置）与 electron-builder 文档：

- portable exe（`…-win-x64-portable.exe`）是自解压程序：每次运行解压到临时目录再启动。它**只带走程序本身**。
- 数据目录**不跟着 exe 走**：不管 exe 放在哪里（U 盘、桌面），数据都在当前 Windows 用户的 `%LOCALAPPDATA%\LocalKnowledgeWorkbench`。应用没有读取 electron-builder 提供的 `PORTABLE_EXECUTABLE_DIR`，也没有“exe 同目录 data 文件夹”模式。把 portable exe 拷到另一台电脑运行 = 一个全新的空工作台。
- 安装版（NSIS）同样把数据放在 `%LOCALAPPDATA%`；卸载默认保留数据。
- 唯一能让数据“跟着走”的方式是手动设置环境变量 `KB_USER_DATA=<U 盘上的目录>`。即使这样，到另一台电脑上：根目录路径仍是旧电脑的（根显示离线，需要在「根目录与缺失文件」重新映射）；`file_key` 来自旧电脑的卷（可能误判重命名）；网页面板的 cookie 用 DPAPI 加密，换电脑/换用户后无法解密（需要重新登录）。所以**推荐用本流程的迁移包**，而不是搬数据目录。
- 不能带走的：原始资料文件（从来不在数据目录里）、网站登录状态、操作记录对应的撤销能力（迁移包也不带）。

## 9. 结果 (b)：应用数据迁移实测（Linux 盒子，xvfb）

单元/集成测试 `tests/migration.test.ts`（12 项）：zip 往返与拒绝越界；导出内容与排除项；写入并发时的一致快照；Windows 风格原路径（`D:\Users\amy\Documents\我的资料库`、`E:\写作 2026`）→ 本机另一套路径导入，工作区/阅读状态/收藏/外观/主题包/插件（安装、授权、存储、能读文件）全部对上、搜索索引重建；缺 1 个文件；暂不映射的根之后重新映射；映射校验；损坏/版本更新/夹带文件的包；三个失败点的自动回退；导入成功后手动回退。

端到端 `e2e/e2e-migration.mjs`（20 项，`KB_E2E_XVFB=1 node scripts/run-e2e.mjs e2e/e2e-migration.mjs`，需先 `npm run build`）：

2. 旧资料路径“下线”（改名），资料复制到 `新电脑/D 盘/资料（搬家后）` 和 `新电脑/E 盘/写作`；全新用户数据目录 B 启动 → 菜单导入 → 自动匹配一个根、「浏览…」选另一个 → 导入。主窗口重新载入后：同一工作区 ID、分组位置与尺寸（±3 px）、标签与当前标签、PDF 页码与缩放、Markdown 滚动位置（±3 px）、外观、收藏（同一批资源 ID）、根目录指向新路径、插件面板无需重新授权、插件存储都一致，令牌样的键为空；重启后仍一致。

## 10. 需要产品决定的问题

> 第 9 轮已定：第 1 条保持明文，导出时提示「包里含路径和插件数据，请妥善保管」；第 4 条在 SDK 加 `storage.nonMigratableKeys`（见 §11）；第 8 条保留 5 份，并提供「立即备份」。其余各条仍待决定。

1. **导出包要不要加密**：现在是明文 zip。包里有工作区名称、文件相对路径、根目录原路径、插件存储内容。可选：密码加密（AES-256-GCM + scrypt，自己实现容器，不再是普通 zip）或保持明文并在导出时提示。
2. **要不要包含原始资料文件**：现在不包含（根目录可能很大，资料一般用网盘/U 盘自己搬）。可选：“包含被收藏/被工作区引用的文件”或“包含整个根”，需要决定大小上限与重复文件处理。
3. **导入是替换还是合并**：现在是替换（带自动备份）。合并需要处理同 id 根、同名工作区、插件版本冲突。
4. **插件存储里的密钥**：只能按键名识别。是否要求插件把敏感数据声明为“不可迁移”（SDK 层面加 `storage.setSecret` / 不导出命名空间）？
5. **根目录原路径要不要写进 manifest**：方便导入时识别（显示原路径），但会暴露用户名等信息；可改为只写最后一段。
6. **便携模式**：是否支持“exe 同目录 `data` 文件夹”（读取 `PORTABLE_EXECUTABLE_DIR`）？若支持，仍需本文的重映射与 `file_key` 处理，且网页登录无法随身。
7. **操作记录与撤销**是否需要迁移（需要同时带上 blobs 与暂存区，体积大）。
8. **备份保留份数**（现在 5 份）与是否提供手动“立即备份”。
