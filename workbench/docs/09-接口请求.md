### R1 · 把 `ctx.process` 接到主进程进程代理（H10），开放外部程序项目（P3）

- **现状**：`src/main/adapters/appLauncher.ts` 的 `AppLaunchService`（权限 → 程序声明 → 找 exe/校验签名与版本 → 频率限制 5 次/10 秒 → 单实例 → 参数模板展开 → **启动前备份** → `spawn(参数数组, shell:false)` → 退出后比较与审计）只在 `tests/app-launch.test.ts` 里被调用。工作台中外部程序条目仍显示“尚未开放”（`CURRENT_PHASE = 2`）。
- **需要改**：
  1. `src/main/index.ts`：创建 `new AppBackupStore(path.join(dataDir,'adapter-data'), DEFAULT_APP_BACKUP_LIMITS)` 和 `new AppLaunchService({ plugins, grants, resolveResource, rootPathOf, findExe: defaultFindExe, verifyExe: verifyExeWindows, spawn, audit, confirmUnprotected }, store)`；启动时与每天一次调用 `store.prune()`。
  2. IPC（`src/shared/pluginIpc.ts` + preload）：`plugin:process.detect / launch / list / focus / close`，参数只有 `{pluginId, adapterId, itemId, programId, templateId, slots}`，**不接受任何路径或命令行字符串**；`onStatus` 推送 `ProcessHandleInfo`（含 `backup` 摘要）。
  3. `src/plugin-runtime/runtime.ts`：`ctx.process` 的 RPC 白名单加入上述方法。
  4. 渲染进程 `SandboxPanel`：external-managed 适配器挂载状态占位面板（面板内容由插件 UiNode 渲染）。
  5. 应用档案 H11（已检测程序路径、版本、签名缓存，用户可“重新检测”）。
  6. `CURRENT_PHASE` → 3。
- **安全影响**：主进程是唯一能启动程序的地方；exe 只能来自清单候选路径（环境变量只展开 `ProgramFiles`/`ProgramFiles(x86)`/`LOCALAPPDATA`/`ProgramW6432`），参数来自固定模板 + 类型化槽位（文件槽位只能是已授权根内的资源 id）。备份目录记录里不含绝对路径。
- **没有它时**：外部程序项目一律“尚未开放”占位；授权框与插件管理已经能显示显示方式与可恢复说明（来自 SDK 文案）。

### R2 · “外部程序备份”界面与“不备份也启动？”确认框

- **需要改**：
  - 插件管理或条目菜单新增“外部程序备份”：列 `store.list()`（时间、插件、程序、文件、大小、是否超限未备份），退出后显示 `store.compare(launchId)` 的“已修改 / 已删除”，按钮“恢复此文件 / 全部恢复”（`store.restore`，恢复前内容另存为一条 `pre-restore` 记录，提供“撤销恢复”）。
  - `confirmUnprotected(info)` 的实现：模态框“<文件> 超过备份上限（64 MB），这次启动不会备份，外部修改不可恢复。仍然启动？”默认按钮“不启动”。
  - 可选：恢复动作写入现有 op_log，使“撤销”统一。**需要产品决定**（见文末）。
- **没有它时**：备份照常写入（R1 接上后），但用户只能通过插件面板看到“启动前已备份 N 个文件”，无法在界面中恢复。

### R3 · 占位里的显示方式文案改用 SDK

- `src/renderer/ui/Placeholder.tsx:27` 自带一份 `MODE_LABEL`（“应用内阅读 / 网页面板 / 外部程序”旧文案），与授权框、插件管理（已用 SDK `displayModeLabel`）不一致。
- **建议**：改为 `displayModeLabel(adapter)`，或用 `DISPLAY_MODE_FACTS[mode].name`（内嵌渲染 / 内嵌网页 / 外部窗口启动）。纯文案，无安全影响。

### R4 · 宿主层面：状态恢复失败时不覆盖原状态

- **现状**：插件 `restoreState` 抛错或返回 `undefined` 时，宿主重置视图并提示“已重置”，**下一次保存就覆盖了旧状态**（数据丢失）。第 9 轮 SDK 模板改为插件侧 `migrateOrPreserve`（旧数据放进 `legacy` 一起保存），e2e 证明此路径不丢数据；但写得不规范的插件仍会丢。
- **建议**：`SandboxPanel`/条目状态保存处：恢复失败时把原状态信封另存为 `item.state.preserved = {v, data, failedAt, pluginVersion}`，后续保存只写 `state`，不动 `preserved`；占位提示“旧状态已保留，可在条目菜单中丢弃”；下次升级再尝试用 `preserved` 恢复。
- **没有它时**：依赖插件遵守模板规范（规范 §8 已写为必须）。

### R5 · 升级（同 id 重装）后重建已打开的面板

- **实测**（`e2e/e2e-lifecycle.mjs`）：升级时如果权限声明没变，**已打开的面板继续运行旧版本代码**，重新打开或重启后才是新版本；权限声明变化触发重新授权时才会重建。
- **建议**：面板 iframe/插件进程的 React key 加上 `plugin.version + installedAt`，安装完成事件触发对应面板重载（先 `getState` 保存，再按新版本 `restoreState`）。
- **需要产品决定**：是否自动重载，还是在面板头显示“已升级，点此重新加载”。

### R6 · e2e 默认列表加入生命周期测试

- `scripts/run-e2e.mjs` 默认列表加 `e2e/e2e-lifecycle.mjs`（停用 / 缺失 / 升级，16 项检查，约 40 秒）。分支上可手动运行：`node scripts/run-e2e.mjs e2e/e2e-lifecycle.mjs`。

### R7 · 例外说明：分支上重新同步了 `src/shared/adapter-sdk/`

- 改了 `src/shared/adapter-sdk/{types,policy}.ts` 与 `index.ts` 的 `ADAPTER_SDK_COMMIT`，**只用** `node scripts/sync-adapter-sdk.mjs /workspace/kb-adapter-sdk` 生成，没有手改（SDK `d2ba4f2`）。
- 同时把 `tests/adapter-plugins.test.ts` 中 `expect(ADAPTER_SDK_COMMIT).toBe(...)` 改为 `'d2ba4f2'`（插件宿主测试，属本组范围）。
- 理由：`tests/adapter-plugins.test.ts` 强制核心副本与 SDK 工作区逐字一致、文件头提交号等于 `ADAPTER_SDK_COMMIT`；SDK 改了 types/policy 而核心不同步，核心单测必然失败。合并时如 main 也同步过 SDK，以重新运行同步脚本的结果为准。

### R8 · 窗口跟踪 / 切到前台 / 关闭（Win32）

- `AppLaunchService` 只跟踪进程；`ProcessHandleInfo.window` 始终是 `searching`，没有实现按 PID 找顶层窗口、`SetForegroundWindow`、`WM_CLOSE`。需要原生模块或 PowerShell 辅助，**只能在 Windows 真机开发与验证**。没有它时，“切到前台 / 关闭”按钮应保持灰色。
