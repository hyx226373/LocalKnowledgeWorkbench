# 应用适配器模板（示例：外部管理的 Notepad++）

显示方式：`external-managed`「**外部窗口启动**」——Notepad++ 在**它自己的窗口**里运行，面板只是状态占位与控制（启动 / 切到前台 / 关闭），**不是内嵌窗口**。阶段：P3。
**完成程度**（能做什么、不能做什么、哪些要在 Windows 真机核对）：见 [`完成程度.md`](完成程度.md)。核心第 9 轮已有主进程的进程代理与启动前备份模块（`src/main/adapters/`，单测用模拟外部程序），但 IPC/界面接线、应用档案（H11）尚未完成，工作台里目前仍显示“尚未开放”占位。

## 为什么示例从“记事本”换成 Notepad++
外部管理的面板要显示“运行中/已退出”、提供“切到前台”，前提是宿主能把**启动的进程**稳定地对应到**它的顶层窗口**。
- **Windows 11 记事本不合适**：`%WINDIR%\System32\notepad.exe` 已是 Store 版记事本的启动桩，启动的进程很快退出，真正的窗口属于另一个（打包应用）进程，且多个文件会合并成同一窗口的标签页。宿主拿到的进程句柄几乎立刻“已退出”，窗口跟踪和退出状态都不可靠。
- **Notepad++ 合适**：经典 Win32 程序（非打包应用、不需要管理员）；模板固定带 `-multiInst`，每次启动都是**独立进程 + 自己的顶层窗口**（窗口类 `Notepad++`），进程一直存活到窗口关闭，按进程句柄 `EnumWindows` 即可找到窗口，退出码就是窗口关闭；`-nosession` 避免它恢复上次打开的其他文件；安装位置固定在 `%ProgramFiles%`（非用户可写），可按签名者校验。它还常见于知识工作者的电脑上，支持 txt/md/log/json 等文本。
- 仍是“尽力而为”：用户若手动去掉 `-multiInst` 之外的方式再开一个实例、或 Notepad++ 弹出 UAC 保存对话框，跟踪仍可能丢失；面板会诚实显示“运行中（窗口未能跟踪）”。

其他可选的经典 Win32 程序（按同样标准判断）：SumatraPDF（需先确认其“新窗口/新实例”参数；便携版在用户目录时必须用 SHA-256）、7-Zip 文件管理器（`7zFM.exe`）。判断标准：非 Store/打包应用、每次启动一个进程且进程活到窗口关闭（或有“新实例”参数）、无需提权、安装在受保护目录、有稳定签名。

## 关于签名校验（填写前务必在目标机核实）
Notepad++ 的代码签名经历过变化：8.8.2 **无签名**，8.8.3–8.8.6 为**自签名**，8.8.7 起改用 GlobalSign 签发的证书。因此模板写 `publisher: "Notepad++"` + `versionRange: ">=8.8.7"`，更早的版本会被判“程序校验失败”而不启动（宁可拒绝）。
在目标机用 `Get-AuthenticodeSignature "C:\Program Files\Notepad++\notepad++.exe" | Format-List` 或 文件属性 → 数字签名 查看签名者名称，**按实际显示值填写 `publisher`**（宿主按证书主体名比对）。若组织要求更严格，改为列出已批准版本的 `sha256`。

## 填写步骤
1. 复制本目录；`package.json` 同文件适配器模板。
2. **manifest.json → permissions[0].programs[0]**：
   - `exeCandidates`：绝对路径或 `%ProgramFiles%\厂商\程序.exe` 等令牌开头；可列多个候选（32/64 位、不同安装位置）。不要写裸文件名（不做 PATH 搜索）。
   - `verify`：`publisher`（按上文核实）+ 可选 `versionRange`；位于用户可写目录（`%LOCALAPPDATA%`、便携版）的程序必须给 `sha256`。
   - `argTemplates`：每个 argv 项是字面量或 `前缀{槽位}`（如 `-n{line}`），槽位类型 `resource`（工作区文件，宿主解析路径）/`enum`/`int`。**没有自由文本参数**，不得含双引号。若程序默认单实例，在模板里固定加它的“新实例”参数，否则窗口跟踪会失效。
   - `windowTracking`：`best-effort` 或 `none`。
   - `backup`（可选，D6 收紧版）：缺省只备份要打开的那个文件。确有必要时用 `backup.include` 声明少量附加文件（相对目标文件夹的 glob，如 `{stem}.*`），不得写 `*`、`**/*` 这类整文件夹模式；改动会让用户重新授权。
3. **app**：`onPanelClose` 用 `leave-running`（产品决定 D4：关闭面板/退出工作台不结束外部程序）；`autoLaunchOnRestore` 必须为 `false`。
4. **src/index.ts**：改 `ADAPTER_ID`、`PROGRAM_NAME`；启动时只传 `ctx.appProfile` 中的 programId/templateId/slots。
5. **test/**：保留“恶意调用”和“静态校验”用例，改成你的程序与模板。
6. `npm test`；README 写 `docs/验收示例.md` C 节真机步骤，并记录在哪个 Windows 版本、程序版本上验证过。

## 外部修改与备份（产品决定 D6 收紧版）
用户在 Notepad++ 中保存的修改不经过工作台的 fileops。宿主在每次启动前**只备份要打开的那个文件**（加上 `backup.include` 声明的附加文件），**不复制整个文件夹**；单次最多 50 个文件 / 64 MB，保留 14 天，备份区总量 1 GB。程序退出后宿主比较哈希，备份范围内被修改的文件**记入工作台的操作记录**（产品决定：不单独做备份列表），面板与操作记录里都可“撤销外部修改”回到启动前内容；工作台当时已关闭的，下次启动时比较。目标文件超过 64 MB 时，宿主先问用户“不备份也启动？”（默认按钮“不启动”），不同意就不启动（`backup-over-limit`）；备份失败不启动（`backup-failed`）。面板显示宿主返回的备份摘要（`handle.backup`，模板 `backupLabel`）。

授权对话框和插件管理的适配器详情会显示（由 SDK `describePermission` 生成）：
- 启动前备份：只备份要用 Notepad++ 打开的那个文件；不会复制整个文件夹
- 可恢复：备份范围内文件在启动前的内容：程序退出后比较，被改动的文件记入操作记录，可撤销回启动前的内容；若工作台在程序退出前关闭，下次启动时先补记关闭期间的改动（标注“工作台关闭期间的外部修改”），程序仍在运行的，之后的改动等它退出后再记
- 可恢复：每次启动最多备份 50 个文件、共 64 MB；目标文件超过上限时启动前会询问“不备份也启动？”（默认不启动）
- 可恢复：启动前备份与记入操作记录的外部改动备份都保留 14 天，到期自动清理；过期后操作记录里那条显示“备份已过期，无法撤销”。备份区总量超过 1 GB 时先删除最旧的启动前备份
- 不可恢复：备份范围以外的文件：程序“另存为”或新建的文件、同文件夹的其他文件、已登记文件夹以外的任何文件；Notepad++ 自己的设置、会话、插件和最近文件列表；注册表与系统设置、网络操作（上传、发送、同步）、打印等程序产生的外部影响；超过 14 天的外部改动（备份已清理）、比较之前就因总量上限被清理的备份、因上限未备份的文件

完整条目见规范 §6.4。

## 运行约束
- 不要长时间同步占用事件循环：约 3 s 无心跳回应宿主会终止插件进程（不影响已启动的 Notepad++）。
- `ctx.process.*` 调用可能以 `code: 'timeout'` 失败（约 15 s，见规范 §6.5）；显示可重试的提示即可，不要循环重试启动。

## 打包与安装（v1：仅开发者模式）
- **`manifest.main` 必须是单文件 ES 模块**（包内相对路径，`.js`/`.mjs`）。宿主以 `import('kbplugin://<插件id>/<main>')` 加载：不解析裸模块名、不带 node_modules、不能拆成多个 chunk。不要直接把 `tsc` 的输出当作 `main`（它保留 `import '@kb-workbench/adapter-sdk'`，在宿主中无法解析）。
- 用核心的打包脚本（esbuild，SDK 导入解析到核心内置副本，`mock-host` 不允许打包）：
  ```bash
  # 在 kb-workbench 目录
  npm run plugin:build -- <本插件源码目录> --out <输出目录>
  ```
  产物：`<输出目录>/manifest.json` + `<输出目录>/dist/index.js`（单文件）。
- 安装（产品决定 D7：没有商店和签名）：工作台 → 侧栏“插件”→“管理插件…”→ 勾选“开发者模式”→“安装本地插件文件夹（开发者模式）…”→ 选输出目录。改代码后重新打包、再次安装即覆盖升级（保留授权与存储）。
- 核心安装检查除 `validateAdapterManifest` 外还要求：插件 id 不以 `builtin.` `demo.` `kb.` 开头；每个适配器 id 以插件 id 为前缀。

## 如何做一个“已验证嵌入”的案例（默认关闭）
**为什么默认关闭**：把外部进程窗口塞进 Electron 窗口（Win32 `SetParent`）不受官方支持；会合并两个进程的输入队列（外部程序卡死会拖住工作台）、DPI 缩放错乱、焦点/输入法/快捷键冲突，且管理员权限程序和 Store 应用根本无法嵌入，程序升级后行为还会变化。所以只能“逐应用、逐版本”验证后作为实验功能开启。Notepad++ 也**未**经嵌入验证。

步骤：
1. 选定**具体版本**的程序，记录 exe SHA-256、产品版本、Windows 版本（含 build）。
2. 在每个目标 Windows 版本上，按 `docs/适配器规范.md` §7 的清单逐项验证（启动/关闭 20 次、程序卡死时工作台不卡、4 种 DPI 与跨显示器、输入法、快捷键、最小化/最大化、拖放、主题切换、睡眠唤醒），把结果写成 `verify/embedding-<程序>-<版本>-<build>.md`。
3. 把 `embedding.example.json` 中的 `embedding` 合并到 `manifest.json` 的 `app`，填写真实哈希、版本、证据路径与已知问题；`enabledByDefault` 保持 `false`。
4. 用户需在设置中打开实验开关并在该项目上单独启用；哈希或 Windows 版本不匹配时宿主自动回落到 external-managed。
5. 程序每次更新都要重新验证并追加记录。
