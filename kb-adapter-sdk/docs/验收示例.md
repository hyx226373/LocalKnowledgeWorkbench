# 验收示例

每类适配器给出两部分：

1. **用户可操作的验收步骤**——在真实 Windows 10/11 上、用打包好的工作台执行；每一步写“操作 → 预期”。前提是核心已实现 `适配器规范.md` §14 中对应的宿主能力（H1–H13）。
2. **自动化测试**——用 `src/mock-host.ts` 在 Node 中运行（`npm test`），覆盖同样的规则。自动化测试证明“适配器 + 规则”正确，**不能**代替真机验收（模拟宿主没有真实 webview、进程、窗口和签名校验）。

记录方式：每条打 ✅/❌，❌ 附截图与复现步骤，存入 `verify/<插件id>-<日期>.md`。

## A. 文件适配器（示例：JSON 查看器，P1）

准备：注册两个根“资料A”“资料B”，各放一个 `.json`；“资料A”放一个 `readme.txt`；在 kb-workbench 中 `npm run plugin:build -- <SDK>\templates\file-adapter --out <输出目录>`，然后插件管理 → 开发者模式 → 安装本地插件文件夹 → 选输出目录（D7）。

## E. 插件停用 / 缺失 / 升级（所有类型，第 9 轮）

准备：任意一个已打开、已保存过视图状态的插件条目（下例用 JSON 查看器，展开了几个节点）。

| # | 操作 | 预期 |
|---|---|---|
| E1 | 插件管理 → 禁用该插件 | 面板变为“适配器已禁用”占位（启用插件 / 用内置阅读器打开（仅本次）/ 从工作区移除）；其他面板正常 |
| E2 | 重启 | 仍为占位；条目没有消失 |
| E3 | 启用 | 面板恢复到禁用前的展开状态 |
| E4 | 退出工作台，删除 `%APPDATA%\本地知识工作台\plugins\<插件id>` 整个文件夹，再启动 | 面板为“缺少适配器”占位（项目与状态已保留，安装后自动恢复）；插件管理里不再列出该插件 |
| E5 | 重新安装同一版本 | 不再询问授权，面板恢复到原状态 |
| E6 | 安装改了版本号且改了权限声明（如扩展名）的新版本 | 重新弹授权框（声明变化）；允许后面板按新版本打开，旧状态经插件迁移钩子迁移后显示，不出现“状态已重置” |
| E7 | 安装一个状态版本更高、但缺少迁移步骤的新版本 → 重启 | 面板显示默认视图 + 警告“旧版本的视图状态无法迁移，已原样保留（没有丢失）”；继续操作并重启后提示仍在、旧数据仍在 |
| E8 | 升级时该面板正开着（权限声明没变） | 不自动重载：面板上方出现提示条「插件已更新，点此重新加载」；点击后按新版本打开 |
| E9 | 插件的 `restoreState` 抛错/返回 undefined（写得不规范的插件） | 面板显示默认视图 + 提示条“旧版本的视图状态无法被当前插件识别，宿主已原样保留”；继续操作、重启后条目里的 `state.preserved` 仍是原状态；装上修好的新版本后自动恢复；“丢弃旧状态”后才删除 |

自动化覆盖：核心 `e2e/e2e-lifecycle.mjs`（夹具 `e2e/fixtures/plugins/stateful`，E1–E9）；SDK `templates/file-adapter/test/json-viewer.test.ts`（迁移失败保留 legacy、保存时写回、丢弃）。
