# 接入任务模板（“帮我接入这个网站/应用”，修订 4）

修订 4（第 9 轮）新增：显示方式如实命名（内嵌渲染 / 内嵌网页 / 外部窗口启动）；外部程序启动前**只备份目标文件**（+ 清单声明的附加文件），并向用户说明哪些改动可恢复；升级时状态迁移失败**保留原状态**；停用 / 缺失 / 升级的验收项；文末“验收标准”可逐条打勾。

用途：把用户的一句“帮我接入这个网站/应用”变成**一个独立的插件任务**，交给执行代理完成。
用法：主代理先和用户确认“一、需收集的输入”，填好下面“二、任务提示词”中的 `【】`，原样发给执行代理。

---

## 一、需收集的输入（缺一项就先问用户，不要猜）

| # | 输入 | 网站 | 应用 | 示例 |
|---|---|---|---|---|
| 1 | 名称与用途 | 网站名、用来做什么 | 程序名、用来做什么 | “MDN，查前端文档” / “Notepad++，快速编辑 txt” |
| 2 | 来源类型 | `web` | `app`（若只是“在应用内看某种文件”，则是 `file`） | — |
| 3 | 范围 | **允许的域名**（精确主机名；如需子域写 `*.example.com` 并说明原因）；页面资源若来自其他域名，另列 `resourceDomains` | **exe 路径**（绝对路径或 `%ProgramFiles%\…`）、签名者（文件属性→数字签名）或 SHA-256、版本 | `developer.mozilla.org` / `%ProgramFiles%\Notepad++\notepad++.exe`，签名者 Notepad++ |
| 4 | 参数（应用） | — | 需要哪些固定参数模板：无参数 / 打开一个工作区文件 / 枚举选项；文件允许的扩展名 | “打开文件：{file}，txt/md/log” |
| 5 | 期望显示方式 | 只能 `in-app-web` | 默认 `external-managed`。若用户想“嵌在面板里”，告知：默认不支持，只能对指定版本做验证后作为实验功能（见规范 §7），本任务不做。另需确认程序是经典 Win32、每次启动一个进程（或有“新实例”参数）、无需提权——否则窗口跟踪不可靠（如 Windows 11 记事本），应如实告知 | — |
| 6 | 要保存的状态 | 例：当前页面（去掉 query）、滚动位置 | 例：上次启动时间、选择的模板 | 不得包含账号、密码、令牌、Cookie、文件正文 |
| 7 | 会话与数据 | Cookie 持久还是临时；保留天数；关闭面板是否清除；是否需要登录（D5：v1 不提供密钥存储，登录态只能留在网页分区里） | 关闭面板时外部程序默认保持运行（D4）；启动前宿主自动备份目标文件（D6），无需插件处理 | — |
| 8 | 离开域名 / 弹窗 / 下载 / 资源域名 | 默认确认后用系统浏览器打开（D2，仅 https、仅被拦截的地址）；**所有弹窗都会被拒绝（含域内）**，依赖弹窗或 HTTP 认证的登录在面板内不可用——要先告知用户；子资源只允许列出的域名（D1）：执行代理用 `curl -sI <页面>` 查看 CSP 头、查看页面脚本中的主机，列出内容必需的资源域名及用途（会显示在授权框中），遥测/广告/同意管理不列；下载拦截或询问 | — | — |
| 9 | 目标阶段 | P2 | P3（核心第 9 轮合并后已开放） | — |
| 10 | 不可迁移的存储键 | 本机路径缓存等只对本机有意义的数据 | 同左 | `storage.nonMigratableKeys: ["cache:*"]` |

## 二、任务提示词（填写后发给执行代理）

```text
你要为「本地知识工作台」开发一个独立的适配器插件。

【插件】
- 插件 id：【例 user.mdn-docs】（小写反向域名）
- 插件名称：【例 MDN 文档面板】
- 来源类型：【web / app / file】
- 显示方式：【in-app-web「内嵌网页」/ external-managed「外部窗口启动」/ in-app-reader「内嵌渲染」】（清单字段 displayMode，必须与来源类型对应；外部程序不得声明或宣传为内嵌窗口）
- 目标阶段：【P1 / P2 / P3】

【范围】
- web：允许域名【developer.mozilla.org】；子资源额外域名【bcd.developer.mozilla.org（兼容性表数据）、*.mdnplay.dev（交互示例 iframe）、mdn.github.io（示例素材）】；homeUrl【https://developer.mozilla.org/zh-CN/】；
       会话【persistent，maxAgeDays=30（插件 30 天未使用即清除），关闭面板不清除】；离开域名【open-external-with-confirm】；弹窗【block】；下载【block】
- app：程序【Notepad++】exe 候选【%ProgramFiles%\Notepad++\notepad++.exe】；校验【publisher: Notepad++（按目标机实际签名者核实）】/【sha256: …】；
       版本范围【>=8.8.7】；参数模板【open-file: ["-multiInst","-nosession","{file}"]，file=resource，扩展名 txt/md/log】【blank: ["-multiInst","-nosession"]】；
       窗口跟踪【best-effort】；关闭面板时【leave-running】；
       启动前备份【只备份要打开的文件（缺省）】/【附加：{stem}.* 等少量 glob，说明为什么需要】——不得声明整文件夹（*、**/*）
- file：扩展名【json】；MIME【application/json】；读取范围【ask-per-root】

【状态】
- 保存：【当前 URL（去掉 query）+ scrollY】；stateSchemaVersion = 1
- 以后改状态结构：提升 stateSchemaVersion，在 restoreState 里用 SDK `migrateOrPreserve` 迁移；迁移失败把旧数据放进 `legacy` 一起保存并提示（照 file 模板），不得让 restoreState 抛错或返回 undefined
- 禁止保存：账号、密码、令牌、Cookie、文件正文；状态 ≤ 2 KB
- 插件存储里只对本机有意义的键（本机路径缓存、设备相关设置）：在 manifest 顶层声明 `storage.nonMigratableKeys`【例 ["cache:*"]】，导出迁移包时排除

【工作方式】
1. 只在新目录 【/workspace/kb-plugins/<插件id>】 中工作（git init）。从 SDK 模板复制：
   /workspace/kb-adapter-sdk/templates/【web-adapter | app-adapter | file-adapter】
   SDK（类型、策略、模拟宿主）以 devDependency 方式引用 /workspace/kb-adapter-sdk，不要复制修改 SDK 源码。
2. 按模板 README 的“填写步骤”逐项完成：manifest.json、src/index.ts、test/*.test.ts、README.md。
   manifest.main 必须是单文件 ES 模块：用核心 `npm run plugin:build -- <插件目录> --out <输出目录>` 打包（只读使用核心脚本，不改核心），
   v1 只能经开发者模式“安装本地插件文件夹”安装（D7）。
   v1 阅读器只能用 UiNode 渲染（没有 target.element）；不得自行拼接 kbfile:// 地址；只在写入时才需要的 fileops.write 声明 optional: true。
3. 严格遵守 /workspace/kb-adapter-sdk/docs/适配器规范.md。

【硬性规则】
- 不要修改核心工作区代码（/workspace/kb-workbench 及其他插件目录一律只读）。
- 如果核心缺少你需要的能力（宿主 API、权限种类、占位类型、UI 组件等），不要绕过、不要打补丁，
  写一份“宿主 API 请求”放在 docs/宿主API请求.md：需要什么、为什么、建议的接口签名、安全影响、没有它时的降级方案。
- 不申请 manifest 之外的任何权限；不使用通配域名 '*'；不声明 cmd/powershell/脚本解释器；参数只用固定模板 + 类型化槽位。
- 显示方式必须诚实：外部程序不得宣称嵌入；README 与面板文字使用“内嵌渲染 / 内嵌网页 / 外部窗口启动”。
- app：README 必须原样写出授权框里的“启动前备份 / 可恢复 / 不可恢复”三行（由 SDK describePermission 生成），并写一份“完成程度”（能做什么、不能做什么、要在 Windows 真机核对什么），格式参照 templates/app-adapter/完成程度.md。

【交付物】
1. manifest.json（通过 validateAdapterManifest，0 错误；插件 id 不以 builtin./demo./kb. 开头，适配器 id 以插件 id 为前缀）
2. src/index.ts（activate 注册适配器；open/mount/getState/restoreState/onPermissionDenied/dispose）
3. test/*.test.ts（用 @kb-workbench/adapter-sdk/mock-host），至少覆盖下方“验收”中可自动化的每一条
4. README.md：用途、权限说明（与授权框一致）、状态字段、已知限制、真机验收步骤
5. docs/宿主API请求.md（如无需求，写“无”）
6. verify/自测记录.md：tsc、测试与 plugin:build 打包的输出原文

【验收】（对照 /workspace/kb-adapter-sdk/docs/验收示例.md 对应小节）
- tsc 0 错误；npm test 全部通过
- 授权提示展示且只列出声明的范围（域名 / exe+模板 / 根+扩展名）
- 拒绝权限 → 该面板占位，工作区其余面板正常恢复
- 重启后状态恢复；切换主题状态不变
- 卸载“保留数据”/“删除数据”行为正确（含网页分区数据）
- web：不能导航到域外（含 @、子域后缀、http、端口、file:、kbfile: 等写法）；资源域名不能顶层导航；弹窗（含域内）/下载按策略处理；授权框列出资源域名；滚动恢复只重试一次
- 所有类型：不长时间同步占用事件循环（宿主约 3 s 无心跳即终止插件进程）；宿主调用以 `code: 'timeout'` 失败时显示可重试提示、不无限重试（规范 §6.5）
- app：恢复工作区不自动启动；不能启动未声明程序；不能注入参数（引号、开关、额外槽位、非法扩展名）
- UI 显示诚实的显示方式标签
- 升级：状态迁移成功时不出现“已重置”；迁移失败时面板提示“已原样保留”，保存后旧数据仍在（mock-host 单测）
- app：启动只备份目标文件（mock-host `backupRecords` 只含目标文件，或含且仅含 backup.include 声明的文件）；目标超限默认不启动；改动 backup 会改变权限指纹
- 真机步骤写进 README，标注“未在真机执行”直到有人执行

【完成后汇报】（中文）：创建的文件、测试结果、关键设计决定、需要产品确认的问题、宿主 API 请求。
```

## 三、主代理的检查清单（收到执行代理结果后）

- [ ] 改动只在插件目录内（`git status` / 目录对比确认核心未被修改）
- [ ] manifest 的域名 / exe / 模板与用户确认的输入一致，没有扩大
- [ ] 测试真的运行过（看原始输出，不只看结论）
- [ ] 宿主 API 请求已汇总给核心负责人，而不是被插件内部“绕过”
- [ ] 若用户要求“嵌入”，答复中已说明默认不支持及原因
- [ ] web：`resourceDomains` 每个都有用途说明、没有遥测/广告类域名；已告知用户改动资源域名会重新询问授权；需要弹窗/嵌入登录的网站已如实告知不可用
- [ ] 显示方式与来源对应，README/面板没有夸大（外部程序写“外部窗口启动”，不写“嵌入”）
- [ ] app：没有声明整文件夹备份；授权框“可恢复/不可恢复”三行已原样写进 README；有完成程度说明，签名者名称标注“需 Windows 真机核对”
- [ ] 改过状态结构的插件：有迁移步骤；迁移失败保留 legacy（看单测）

## 四、验收标准（交付即检查，全部满足才算完成）

| # | 标准 | 怎么查 |
|---|---|---|
| 1 | 权限边界不变：网站只能访问声明的域名（子资源只 `domains ∪ resourceDomains`）；应用只能启动声明的 exe + 固定参数模板；都要用户授权 | manifest 对照用户输入；mock-host 单测“域外导航/注入参数/未声明程序”全部被拒；授权提示 `scopeLines` 断言 |
| 2 | 显示方式如实声明并显示 | `validateAdapterManifest` 0 错误；单测断言 `displayModeLabel`（内嵌渲染 / 内嵌网页 / 外部窗口启动） |
| 3 | 外部程序启动前只备份目标文件（或明确声明的少量附加文件），说明可恢复/不可恢复 | 单测 `backupRecords`；`scopeLines` 含“启动前备份 / 可恢复 / 不可恢复” |
| 4 | 停用 / 缺失 / 升级都保留条目与状态，升级迁移失败不丢数据 | mock-host：禁用→`adapter-disabled` 占位、启用后恢复；卸载保留数据→`adapter-missing`；迁移失败→`legacy` 保留（核心另有 e2e-lifecycle 覆盖宿主侧） |
| 5 | 状态小且无秘密/正文；重启恢复；主题切换不变 | 单测 |
| 6 | 打包与安装 | `npm run plugin:build` 输出原文；开发者模式安装步骤写进 README |
| 7 | 测试与类型检查 | `tsc` 0 错误、`npm test` 全通过（贴原始输出） |
| 8 | 真机项诚实标注 | README“真机验收”逐条标“未执行/已执行（日期、Windows 版本、程序版本）” |
