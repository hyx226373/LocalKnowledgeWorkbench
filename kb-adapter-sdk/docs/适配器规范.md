# 适配器规范（Adapter API v0.1，修订 10：第 11 轮——逐站授权（内置通用网页）；修订 4–9 见 §16）

> 适用：本地知识工作台（Electron + TypeScript + React，Windows 单窗口）。
> 代码：`src/types.ts`（类型，零运行时依赖）、`src/policy.ts`（规则参考实现）、`src/mock-host.ts`（模拟宿主）。
> 本文是规范正文；类型注释是摘要。与核心现有文档的关系：本规范扩展 `kb-workbench/docs/02-技术方案.md` §10（布局模型）与 §11（插件架构），需要核心配合的地方集中列在 §14。核心已实现 H1–H9 与健壮性机制（见 `kb-workbench/docs/06-适配器宿主.md`）；修订 2/3 吸收了其 §10、§10.1 列出的差异，并记录产品决定 D1–D7（§15）。修订记录见 §16。

## 0. 术语

| 术语 | 含义 |
|---|---|
| 项目（item） | 工作区中一个可放进面板的东西：一个文件、一个网页、一个外部程序档案 |
| 来源类型 sourceKind | `file` / `web` / `app` |
| 适配器（adapter） | 插件贡献的“如何打开某类项目”的实现。所有兼容性逻辑都在适配器里 |
| 核心 / 宿主（core / host） | 工作台本体。只负责：把项目放进布局、启用/禁用插件、授权、恢复状态、显示占位 |
| 显示方式 displayMode | 适配器对“内容到底显示在哪里”的诚实声明 |
| 应用档案 AppProfile | 核心保存的“程序 + 参数模板 + 槽位取值”，是 app 项目的 `ref` |

## 1. 原则

1. **核心只编排，不兼容**：核心不认识 JSON、MDN、Notepad++；它只按 `adapterId` 找适配器，判定能否打开，否则显示占位。
2. **诚实的显示方式**：`file → in-app-reader`，`web → in-app-web`，`app → external-managed` 一一对应，manifest 校验强制。任意 Windows 程序无法可靠嵌入面板；“嵌入”只能作为逐应用、逐版本验证过的实验增强（§7），默认关闭。
3. **最小且有范围的权限**：没有“任意文件 / 任意网络 / 任意进程”。每项权限都带范围（根、扩展名、域名、exe+参数模板），由用户批准，可撤销。
4. **失败局部化**：任一项目打不开只影响它自己的面板（占位），其余工作区照常恢复；占位**不改写**项目的 adapterId 与 state，条件恢复后自动复原。
5. **状态小而干净**：只存“看到哪里”（页码、滚动、展开节点、URL 路径），不存秘密、不存文件正文，带版本可迁移。
6. **分阶段开放**：P1 文件阅读器 + 工作区面板；P2 网页面板；P3 指定本地应用适配器。v1 的第三方插件只有沙箱视图插件（file 适配器，只用 UiNode 渲染）；web/app 适配器在后续阶段开放，阶段未到时项目显示“尚未开放”占位且不弹授权。v1 第三方插件**只能经开发者模式从本地文件夹安装**，没有商店、签名、自动更新（D7）。

## 2. 项目模型

```ts
interface WorkspaceItem {
  itemId: string;                 // UUID，布局面板只引用它
  sourceKind: 'file' | 'web' | 'app';
  adapterId: string;
  ref: string;                    // file: resourceId；web: URL；app: appProfileId
  displayMode: DisplayMode;       // 创建时取自适配器声明；打开时以适配器当前声明为准显示标签
  state?: { v: number; data: JsonValue } | null;  // 版本化、≤16 KB、无秘密、无正文
  title?: string;
}
```

- **布局 schema 4**（核心编号；schema 3 在核心第三轮已用于“条目内联在布局里”）：`{schema:4, dock, shell}`，不含条目；dock 中每个面板 `params` 只有 `{itemId}`，条目单独存表。核心迁移：schema 1/2 的面板 `{viewType, resourceId, state}` → 生成 `sourceKind:'file'` 条目（`adapterId = viewType`，`ref = resourceId`，`state = {v:1, data: 旧 state}`）；schema 3 的内联 `items` 拆进表。恢复时剪掉引用不存在条目的悬空面板。
- **项目表**（核心已实现）：`workspace_items(workspace_id, item_id, source_kind, adapter_id, ref, display_mode, state_json, title, created_at, updated_at, PK(workspace_id,item_id))`；P3 再加 `app_profiles(app_profile_id PK, adapter_id, program_id, label, launch_json)`。`ref` 中不出现绝对路径；web 的 `ref` 保存前用 `sanitizeUrlForState` 处理——它**去掉整个 query 串**（以及 userinfo），只保留 `origin + path + hash`；依赖 query 才能定位内容的网站要在适配器状态里另存所需的最小参数（不得是令牌）。
- **应用档案**由用户在“添加外部程序项目”向导中创建：选适配器 → 选程序（manifest 声明的）→ 选参数模板 → 填槽位（资源槽位用工作台文件选择器选 resourceId）。适配器只能读取档案，不能修改。

## 3. Manifest

### 3.1 示例（文件适配器）

```jsonc
{
  "id": "example.json-viewer",                 // 小写反向域名，规则同核心 PluginManifest.id
  "name": "JSON 查看器（示例）",
  "version": "0.1.0",
  "engines": { "workbench": "^0.2.0", "adapterApi": "^0.1.0" },
  "main": "dist/index.js",
  "activationEvents": ["onAdapter:example.json-viewer.reader"],
  "sandbox": "iframe",                         // v1 第三方插件只能是沙箱 iframe
  "contributes": {
    "adapters": [{
      "id": "example.json-viewer.reader",
      "title": "JSON 树",
      "sourceKinds": ["file"],                 // v0.1 恰好一项
      "displayMode": "in-app-reader",          // 必须与 sourceKind 对应
      "match": { "file": { "extensions": ["json"], "mimeTypes": ["application/json"], "maxSizeBytes": 10485760 }, "priority": 150 },
      "permissions": [
        { "id": "read-json", "kind": "fs.read", "scope": "ask-per-root", "extensions": ["json"], "reason": "读取你打开的 JSON 文件，以树形显示" }
      ],
      "stateSchemaVersion": 2,
      "stateMigrations": [{ "from": 1, "to": 2, "note": "open 改名 expanded，新增 showTypes" }],
      "maxStateBytes": 8192
    }]
  }
}
```

web / app 示例见 `templates/web-adapter/manifest.json`、`templates/app-adapter/manifest.json`。

**分发格式**：插件包是一个文件夹，含 `manifest.json` 与 `main` 指向的文件。`main` 必须是包内相对路径（`.js`/`.mjs`）的**单文件 ES 模块**——宿主以 `import('kbplugin://<id>/<main>')` 加载，不解析裸模块名、不带 node_modules。用核心的 `npm run plugin:build -- <插件源码目录> --out <输出目录>` 打包（esbuild，把 `@kb-workbench/adapter-sdk[/policy|/types]` 解析到核心内置的 SDK 副本；`mock-host` 禁止打包）。核心安装时另加检查：插件 id 不得以 `builtin.` `demo.` `kb.` 开头、不得与内置插件重名，每个适配器 id 必须以插件 id 为前缀。

### 3.2 `contributes.adapters[]` 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 全局唯一，建议 `<pluginId>.<名称>`；写入项目的 `adapterId` |
| `title` / `description` | title 是 | 显示在“打开方式”、占位、插件管理页 |
| `sourceKinds` | 是 | v0.1 必须恰好一项（数组为将来多来源预留） |
| `displayMode` | 是 | `in-app-reader` / `in-app-web` / `external-managed`，与 sourceKind 固定对应 |
| `match` | 是 | `file:{extensions,mimeTypes,maxSizeBytes}` / `web:{urlPatterns}` / `app:{programIds}`，`priority ≤ 200`（与核心视图优先级同档：内置 100、回退 1） |
| `permissions` | 是 | 权限声明数组（§4）。每类适配器必须有一项非可选的主权限：file→`fs.read`，web→`net`，app→`process.launch` |
| `stateSchemaVersion` | 是 | 正整数，从 1 开始；状态结构变化时 +1 |
| `stateMigrations` | 否 | 声明已实现的迁移 `{from,to,note}`，供商店展示与静态检查；代码在 `restoreState` 中实现 |
| `maxStateBytes` | 否 | ≤ 16384，只能调小 |
| `web` | web 必填 | `homeUrl`、`session{partition:'persistent'|'ephemeral', clearOnClose?, maxAgeDays?}`、`offDomain`、`popups`、`downloads` |
| `app` | app 必填 | `programIds`、`onPanelClose:'leave-running'|'ask'|'close-gracefully'`、`autoLaunchOnRestore:false`（固定）、`embedding?`（§7） |

插件级（manifest 顶层，修订 5）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `storage.nonMigratableKeys` | 否 | 插件私有存储里**不可迁移**的键：只对本机有意义的数据（本机路径缓存、设备相关设置等）。写完整键名，或以 `*` 结尾表示前缀（如 `cache:*`）；不允许单独的 `*`；最多 32 条（`storageDeclErrors`，安装时校验）。核心“导出迁移包”时排除这些键（`isNonMigratableKey`），并在包的 manifest 里记下排除的数量。像密钥的键（password/token/…）无论是否声明都不导出 |

### 3.3 校验规则（`validateAdapterManifest`，安装时执行，不通过则“已安装但不兼容”，显示原因）

- id / version / `engines.adapterApi` 满足当前 `ADAPTER_API_VERSION`；`sandbox === 'iframe'`。
- displayMode 与 sourceKind 对应；适配器只能申请本类允许的权限（file: `fs.read`、`fileops.write`；web: `net`；app: `process.launch`）。
- net：域名必须是小写精确主机或 `*.子域通配`（至少两级，如 `*.example.com`）；禁止 `*`、IP、端口、协议、路径、尾随点。宿主还应以公共后缀列表拒绝 `*.github.io` 之类。
- web：`homeUrl` 与 `match.web.urlPatterns` 必须落在声明域名内。
- net.mode（修订 10）：缺省 `listed`。`ask-per-site`（逐站授权）**只允许随包内置的适配器声明**（`validateAdapterManifest(m, v, { source: 'builtin' })`）；第三方插件声明即“已安装但不兼容”，安装被拒绝。逐站授权时 `domains` 可以为空（仍不得含 `*`/IP/端口），`homeUrl` 只需是合法的 http(s) 地址，`match.web.urlPatterns` 可省略（宿主把它当作任意网址的兜底适配器）。
- process.launch：exe 必须为绝对路径或以 `%WINDIR%` `%SystemRoot%` `%ProgramFiles%` `%ProgramFiles(x86)%` `%LOCALAPPDATA%` 开头，只允许 `.exe`，不得含 `.`/`..` 段，不得是解释器/系统代理执行程序（`FORBIDDEN_EXE_NAMES`：cmd、powershell、wscript、mshta、rundll32、explorer…）；必须声明 `sha256` 或 `publisher`（否则显式 `unverified:true`，授权框警告）；参数模板每项只能是字面量或 `前缀{slot}`，不得含双引号/控制字符，槽位必须声明且都被使用；`backup.include` 每条须通过 `backupGlobError`（相对目标文件夹、无 `..`/绝对路径/反斜杠、不能只有通配符），最多 8 条。
- app：`autoLaunchOnRestore` 必须为 false；`embedding.enabledByDefault` 必须为 false，且每条验证记录有 exe 哈希、Windows 版本、证据。

## 4. 权限模型

### 4.1 四种权限

| kind | 范围参数 | 用户看到的说明（`describePermission`） | 宿主执行点 |
|---|---|---|---|
| `fs.read` | `scope: ask-per-root | all-registered-roots`，`extensions?` | “读取你勾选的已注册文件夹中的文件（只读）/ 仅限扩展名… / 看不到绝对路径” | `files.*` 每次调用按 resourceId → 根 → 授权根列表 → 扩展名检查；路径校验沿用核心 §4（realpath、junction、大小写） |
| `fileops.write` | `operations: write/move/trash` | “每一批修改先显示计划，经你批准后执行，可撤销” | 只能 `files.requestFileops(plan)`；核心显示批量计划对话框 → fileops 服务执行 → `op_log` actor=`plugin:<id>`。必需时打开即询问；`optional:true` 时首次 `requestFileops` 才询问（见 4.2） |
| `net` | `domains`、`resourceDomains?`、`mode?: 'listed' \| 'ask-per-site'`（修订 10） | “仅限域名：developer.mozilla.org” | 顶层导航、重定向、子框架、弹窗、子资源全部按域名检查（§6.3） |
| `process.launch` | `programs[]`（exe 候选、校验、参数模板） | “仅可启动：Notepad++（%ProgramFiles%\Notepad++\notepad++.exe …）/ 校验：签名者 … / 参数模板「打开文件（独立实例）」：-multiInst -nosession {file} / 不能启动其他程序，不能附加自定义参数” | 主进程进程代理（§6.4） |

### 4.2 授权流程

1. **何时询问**：首次打开使用该适配器的项目时，对每个**必需**权限询问（不是安装时，避免一次弹出一串）；也可在插件管理页预先授权。阶段未开放、插件禁用、文件不存在时不询问。
   - **可选权限**（`optional: true`）打开时不询问，推迟到插件调用 `ctx.permissions.request(id)` 或首次使用时。典型：`fileops.write` 若声明为必需，用户一打开文件就会被问“允许修改吗”；只在用户点“整理/保存”时才需要写的插件应声明 `optional: true`，首次 `requestFileops` 时宿主先弹授权框，再弹批量计划对话框。
2. **对话框内容**（`PermissionPromptRequest`）：插件名、适配器名、**显示方式标签**、权限理由、宿主生成的范围说明（插件不能自定义范围文字）。`ask-per-root` 时列出已注册根供勾选。
3. **记录**：`PermissionGrant{pluginId, adapterId, permissionId, decision, rootIds?, declHash}` 存入 `plugins.granted_json`。`declHash` 是权限声明的指纹：插件升级后声明变化（例如多了一个域名）→ 原授权失效，重新询问；**拒绝**记录不随指纹失效（不反复打扰），用户可在插件管理页改为允许。
4. **拒绝**：必需权限被拒 → 项目显示 `permission-denied` 占位（按钮“查看权限”），其余工作区不受影响；可选权限被拒 → 适配器照常打开，收到 `onPermissionDenied`。
5. **撤销**：插件管理页可逐项撤销；必需权限被撤销 → 已打开面板立即换成占位；可选权限 → `onPermissionDenied({reason:'revoked'})`。
6. **越界调用**（读未授权根的文件、导航到域外、启动未声明程序）→ 宿主拒绝该次调用（`HostPermissionError` / `{ok:false, reason}`），并调用 `onPermissionDenied({reason:'out-of-scope'})`；不弹窗、不扩大授权。

## 5. 生命周期

```
安装(校验manifest) → 启用 → [首次需要时] activate(api) → api.adapters.register(impl)
   ↓ 打开项目（核心判定顺序见 5.1）
impl.restoreState(data, v) → impl.open(item, ctx) → instance.mount(target)
   ↺ 运行中：ctx.requestSave() → 宿主去抖 → instance.getState() → 校验 → 写 item.state
   ↺ instance.onThemeChange(theme) / onVisibilityChange(visible) / onPermissionDenied(denial)
关闭面板 / 禁用 / 卸载 / 退出 → instance.dispose() → [插件全部面板关闭且禁用时] deactivate()
```

| 钩子 | 签名 | 要求 |
|---|---|---|
| `activate` | `(api: AdapterHostApi) => void|Promise` | 只注册，不做重活；抛错 → 插件“出错”，其适配器的项目显示 `adapter-error` |
| `open` | `(item, ctx: OpenContext) => AdapterInstance` | 可异步；`ctx` 中只有本类型且已授权的 API（file 有 `ctx.files`，app 有 `ctx.process`/`ctx.appProfile`） |
| `mount` | `(target: MountTarget)` | `reader`/`external` 目标用 `render(UiNode)` + `onAction`；`web` 目标拿到 `WebPanelHandle`。抛错 → `adapter-error` 占位 |
| `getState` | `() => S | undefined` | 同步、便宜；返回 undefined 表示不保存 |
| `restoreState` | `(data: unknown, fromVersion) => S | undefined` | 在 impl 上（不在实例上），先迁移后校验；返回 undefined → 默认状态 + “状态已重置”提示 |
| `onPermissionDenied` | `(denial)` | 降级显示，不抛错 |
| `onThemeChange` | `(theme)` | 状态不得改变；用 UiNode 的适配器通常无需处理 |
| `dispose` | `()` | 释放订阅；app 适配器按 `onPanelClose` 处理外部进程（默认 leave-running） |

### 5.1 核心打开项目的判定顺序（`MockHost.doOpen` 即参考实现）

1. 找不到 adapterId → `adapter-missing`
2. 插件不兼容 → `adapter-incompatible`；插件已禁用 → `adapter-disabled`
3. 当前阶段未开放该 sourceKind → `phase-unavailable`
4. file 资源不存在 → `resource-missing`（不为不存在的文件弹授权）
5. 逐项**必需**权限：无记录或声明已变化则询问；被拒 → `permission-denied`（可选权限跳过）
6. 范围预检：file 不在授权根/扩展名 → `permission-denied`；web 的 `ref` 不在域名内 → `domain-blocked`；app 档案缺失 → `adapter-error`，程序未安装 → `app-not-installed`，签名/哈希/版本不符 → `app-verification-failed`
7. 恢复状态（无效 → 默认 + 提示，不算失败）
8. `open` → `mount`，任何异常或沙箱 15 秒未就绪 → `adapter-error`（ErrorBoundary / iframe 崩溃同理）

## 6. 宿主 API

### 6.1 通用（`AdapterHostApi`）

| 成员 | 说明 |
|---|---|
| `pluginId` / `hostVersion` / `adapterApiVersion` / `phase` | 只读 |
| `adapters.register(impl)` | `impl.id` 必须在 manifest 中声明，否则抛错 |
| `storage.get/set/delete/keys` | 插件私有命名空间（核心 `plugin_kv`），单值 ≤1 MB、总量 ≤10 MB；禁止存秘密（v1 无加密存储，见 §15） |
| `theme.current()` / `theme.onDidChange` | 只读令牌快照；沙箱 iframe 由宿主注入 `--kb-*` CSS 变量 |
| `log.info/warn/error` | 写入插件日志（插件管理页可查看） |

**UI**：`UiMountTarget.render(UiNode)` 接收声明式树（text/heading/code/badge/button/stack/keyValue/tree/notice），宿主重新构造节点（只保留已知字段，深度 ≤32、节点 ≤5000）后只用文本节点绘制、样式全部来自主题令牌——没有 HTML 注入面，切换主题自动生效。

**v1 只有 UiNode**：核心的沙箱 iframe 是隐藏的，只运行代码。`ReaderMountTarget.element`（插件自绘 DOM）**v1 不提供**，类型中标为 `@deprecated`、宿主始终传 `undefined`，仅为类型兼容保留。需要自绘的阅读器（pdf.js、canvas、图片查看）要等后续版本让 iframe 可见并解决尺寸/焦点/快捷键桥接，形式届时另定。

### 6.2 file（`ctx.files: FileHostApi`）

| 方法 | 说明 |
|---|---|
| `stat(resourceId)` | 名称、扩展名、大小、mtime、是否存在；无绝对路径 |
| `readText(resourceId, {maxBytes})` | 默认上限 5 MB，返回 `truncated` |
| `readBytes(resourceId, {offset,length})` | 分段读取大文件 |
| `contentUrl(resourceId)` | 只读内容 URL。**形式由宿主决定，插件不得自行拼接、解析或缓存跨面板使用**。核心 v0.2 返回 `kbfile://plugin/<面板令牌>/<resourceId>`：令牌绑定插件+适配器，每次请求按当前授权重新检查，禁用/撤销后立即失效；`kbfile://res|root` 不按插件授权，沙箱 CSP 不允许访问。v1 没有可显示图片的 UiNode，此方法为后续版本预留 |
| `onDidChange` | 资源被修改/删除/移动（来自核心监听器） |
| `requestFileops(plan)` | 仅声明 `fileops.write` 时存在；用户在批量计划对话框中批准后由 fileops 服务执行，可撤销 |

### 6.3 web（`target.web: WebPanelHandle`）

| 方法/事件 | 说明 |
|---|---|
| `partition` | 宿主派生、只读：持久 `persist:kbweb.<pluginId>`，临时 `kbweb-mem.<pluginId>`。**每个插件一个分区**，插件之间、与工作台主会话之间不共享 Cookie/存储 |
| `allowedDomains` | 来自 manifest，只读 |
| `navigate(url)` | 返回 `{ok}` 或 `{ok:false, reason:'domain-blocked'|'scheme-blocked'|'invalid-url'|'permission-denied'}`；只允许 https、默认端口、无 userinfo。子资源只允许 `domains ∪ resourceDomains`（D1） |
| `back/forward/reload` | 常规 |
| `currentUrl()` | 宿主**缓存值**（主进程导航完成事件后更新）：刚调用 `navigate` 后可能仍是旧地址；需要确切地址时以 `onDidNavigate` 为准 |
| `getScroll/setScroll`、`onScroll` | 宿主在隔离世界中读写滚动位置（插件不能注入脚本；核心约每 300 ms 轮询一次、变化时发 `onScroll`）。**恢复是尽力而为**：`setScroll` 到达目标后，页面晚加载的内容（图片、广告位）与浏览器滚动锚定仍可能把位置推走，宿主不会无限“追着页面改滚动”（核心的 `setScroll` 在页面内容仍在增长时最多重试约 3 s）。模板做法：在 `onLoadState('ready')` 时 `setScroll`，恢复期间的 `onScroll` 不写入状态，等页面“稳定”（约 1.2 s 无滚动变化，最多等 5 s）后检查一次、偏差超过 8 px 就**只重试一次** |
| `onDidNavigate`、`onLoadState`、`onBlocked` | 被拦截的导航/弹窗/下载由宿主在面板顶部横幅提示；按 D2，离开域名的链接默认提供“用系统浏览器打开”，点击后再确认一次才调用系统浏览器（只允许 https） |
| 状态中的 URL | 适配器保存 URL 前应调用 `sanitizeUrlForState`：**去掉整个 query 串**和 userinfo，只留 origin+path+hash；核心保存 web 条目 `ref` 时也这样处理 |
| `clearSessionData(kinds)` | 清除本插件分区的 Cookie/存储/缓存 |

**Cookie / 存储保留策略**：`persistent` 分区保留到用户清除、**该插件连续 `maxAgeDays` 天未使用**（未创建过网页面板；宿主记录最近使用时间，启动时清除整个过期分区——不是单个 Cookie 的年龄）或卸载时选择删除；`ephemeral` 只在内存，退出即丢；`clearOnClose` 在该插件最后一个面板关闭时清除。网页会话数据**不进入**工作台备份导出（可能含登录凭据），插件管理页显示其占用并提供“清除网站数据”。

宿主面板外框固定显示：显示方式标签“网页面板 · 仅限 <域名>”、后退/前进/刷新、只读地址（不可输入任意 URL）、“已拦截 N 个外部资源”计数。

**可见性**：网页是主进程的原生视图（WebContentsView），画在工作台 DOM 之上、无法与 DOM 混排。宿主**可以在工作台浮层（对话框、菜单、命令面板、拖动标签）与网页区域相交时临时隐藏网页视图**，用最近一帧截图代替；非活动标签中也会隐藏。这些情况**不通知插件**（不触发 `onVisibilityChange`），插件不得依赖网页一直可见或一直在接收输入。

**登录**：v1 不提供“应用内嵌登录”。HTTP 认证（`login`）、客户端证书被拒绝；依赖弹窗的 OAuth/第三方登录不能在面板内完成（弹窗一律被拒，见 §12.2）。只能在允许域名内的页面本身登录，登录态留在该插件分区（D5）。

**逐站授权**（修订 10，`net.mode = 'ask-per-site'`，仅内置适配器，如核心随包的通用网页 `web.generic`）：
- 首次导航到某个主机（打开条目、页面内链接、重定向、宿主“打开网址”）时，宿主弹框询问“允许访问 <主机名>？”；用户批准后把**精确主机名**写入该适配器的 `PermissionGrant.grantedHosts`（`withGrantedHost`）。不批准通配、IP、端口；`localhost` 这类单级主机名也不批准。
- 允许集合 = `domains ∪ grantedHosts`（`netAllowedHosts`）；子框架/子资源/弹窗/下载 = 再并上 `resourceDomains`（`netResourceHosts`）。判定用 `checkSiteNavigation`：`ok` / `site-not-granted`（附主机名，宿主据此询问）/ 其他拒绝原因（协议、IP、端口、userinfo——不询问，直接拦）。
- 重定向只跟到已批准主机；跳到未批准主机时宿主取消这次重定向并询问，批准后再导航过去，拒绝则拦截。
- 用户拒绝：条目显示“未授权”占位（可“允许访问此网站”或“用系统浏览器打开”）；页面内导航被拒只显示横幅。
- 逐站授权的适配器可以打开 **http** 地址（`checkNavigation(url, hosts, { allowHttp: true })`），同样只限已批准主机，宿主外框标注“不安全连接”。listed 模式仍只允许 https。
- `grantedHosts` 只在授权记录 `decision === 'granted'` 且 `declHash` 与当前声明一致时生效；撤销 = 写入拒绝记录（全部主机失效）；插件管理可逐个撤销主机（`withoutGrantedHost`）。
- 插件代码拿不到“批准主机”的能力：询问与写授权只在宿主进行；`navigate()` 到未批准主机返回 `domain-blocked`。

**用系统浏览器打开**（D2）：插件没有这个 API。只有宿主提供该按钮（横幅或 `domain-blocked` 占位），并且只对满足以下全部条件的地址：https、无 userinfo、是**宿主在该面板最近拦截的地址**或**条目自己的 `ref`**；二次确认后才调用系统浏览器。

### 6.4 app（`ctx.process: ProcessBrokerApi`，主进程进程代理）

| 方法/事件 | 说明 |
|---|---|
| `detect(programId)` | 是否安装、是否通过校验、版本、失败原因；不返回路径 |
| `launch({programId, templateId, slots})` | 代理按 §12.3 校验并启动；返回 `ProcessHandleInfo`（launchId、状态、pid、窗口跟踪状态）——**不含 exe 路径和 argv** |
| `focus(launchId)` | 已跟踪到窗口时切到前台（`AllowSetForegroundWindow` + `SetForegroundWindow`），否则 false |
| `close(launchId, {force})` | 先 `WM_CLOSE` 优雅关闭；`force` 需用户确认后才终止；只能关闭本插件启动的进程 |
| `list()` | 本插件启动且仍被跟踪的进程（面板重开时接回） |
| `onStatus` | `starting/running/exited/crashed` 与窗口跟踪 `not-tracked/searching/found/lost` |

**窗口跟踪是尽力而为**：代理按进程句柄（不是 pid，防 pid 复用）与其子进程枚举顶层窗口。已知会失败的情形：Windows 11 的 `notepad.exe`、计算器等是 Store 应用的启动桩（启动的进程立即退出，窗口属于另一进程）；单实例程序把请求转交已运行实例；以管理员身份运行的程序（UIPI）。失败时面板诚实显示“运行中（窗口未能跟踪）”，“切到前台”不可用。

外部面板固定显示标签“外部窗口启动 · 程序在自己的窗口中运行，本面板只显示状态占位（不是内嵌窗口）”。恢复工作区**从不**自动启动外部程序。关闭面板或退出工作台时外部程序**继续运行**（D4，`onPanelClose` 缺省 `leave-running`）。

**启动前备份**（D6 收紧版，修订 4）：**不复制整个已注册根**。每次 `launch` 通过校验、即将 spawn 时，代理只备份：

1. 资源槽位指向的**目标文件**（要用外部程序打开的那个文件）；
2. 适配器在 `programs[].backup.include` 中**明确声明**的附加文件：相对于目标文件所在文件夹的 glob（`*` `?` `**` `{stem}`），只匹配同一已注册根内的普通文件；禁止绝对路径、`..`、反斜杠、只由通配符组成的模式（`*`、`**/*`、`*.*`），最多 8 条（`backupGlobError`）。`backup` 属于权限声明：改动后 `declHash` 变化，需重新授权。

计划由 `planAppBackup` 计算（宿主与模拟宿主共用）。上限与保留期（`DEFAULT_APP_BACKUP_LIMITS`，宿主可调）：每次启动最多 50 个文件、共 64 MB（目标文件优先，附加文件按路径排序，放不下的跳过并计数）；**目标文件本身超过 64 MB → 不备份，启动前必须由用户确认“不备份也启动”，否则 `backup-over-limit`**；备份保留 14 天；备份区总量超过 1 GB 时先删最旧的。备份失败（读不到文件、写不进备份区）→ `backup-failed`，不启动。`ProcessHandleInfo.backup` 只给适配器数量摘要（`files/bytes/skipped/targetUnprotected`），不给路径。程序退出后宿主比较哈希，备份范围内被修改的文件**记入核心的操作记录**（产品决定，修订 5：恢复入口是操作记录的统一撤销，不单独做备份列表），可撤销回启动前内容；撤销前文件又被改过时先确认，并保留两份。工作台在程序退出前关闭的（修订 7）：下次启动时先比较所有未结束会话的目标文件，把关闭期间的改动补记进操作记录并标注“工作台关闭期间的外部修改”；程序仍在运行的，把当时的内容设为新基准，等它退出后只记新基准之后的改动（工作台运行中、程序还没退出时不提前记）。超限确认框的默认按钮是“不启动”。

**哪些外部改动能恢复、哪些不能**（`describeAppRecovery` 生成；授权对话框与插件管理的适配器详情通过 `describePermission` 显示全部条目（修订 9：“启动前备份”一行、每条“可恢复”各一行、“不可恢复”全部条目合成一行；内容过长时宿主让授权框可以滚动），下面是完整原文，以 Notepad++ 为例）：

- 启动前备份：只备份要用 Notepad++ 打开的那个文件；不会复制整个文件夹
- 可恢复：
  - 备份范围内文件在启动前的内容：程序退出后比较，被改动的文件记入操作记录，可撤销回启动前的内容；若工作台在程序退出前关闭，下次启动时先补记关闭期间的改动（标注“工作台关闭期间的外部修改”），程序仍在运行的，之后的改动等它退出后再记
  - 每次启动最多备份 50 个文件、共 64 MB；目标文件超过上限时启动前会询问“不备份也启动？”（默认不启动）
  - 启动前备份与记入操作记录的外部改动备份都保留 14 天，到期自动清理；过期后操作记录里那条显示“备份已过期，无法撤销”。备份区总量超过 1 GB 时先删除最旧的启动前备份
- 不可恢复：
  - 备份范围以外的文件：程序“另存为”或新建的文件、同文件夹的其他文件、已登记文件夹以外的任何文件
  - Notepad++ 自己的设置、会话、插件和最近文件列表
  - 注册表与系统设置、网络操作（上传、发送、同步）、打印等程序产生的外部影响
  - 超过 14 天的外部改动（备份已清理）、比较之前就因总量上限被清理的备份、因上限未备份的文件

**选择示例程序的原则**：模板用 Notepad++（经典 Win32、`-multiInst` 每次独立进程、窗口类固定），而不是 Windows 11 的记事本（Store 应用启动桩，窗口不属于启动的进程）。详见 `templates/app-adapter/README.md`。

### 6.5 运行约束：事件循环、超时与看门狗（所有类型）

插件代码运行在沙箱 iframe 中；核心让每个插件在独立渲染进程中运行（同一插件的多个面板共用一个进程），由宿主看门狗监控。插件必须遵守：

| 约束 | 宿主行为（数值为核心当前实现，约值，可能调整） |
|---|---|
| **不得长时间同步占用事件循环**（大循环、同步解析超大数据要分段 `await`） | 宿主约每 0.5 s 发心跳，约 **3 s** 无回应即判卡死：终止该插件进程，它的**所有**面板变为 `adapter-error` 占位（可重试），写审计 `watchdog` |
| 不得洪泛消息 | 1 秒内超过约 400 条消息按卡死处理 |
| `activate` / `open` / `mount` 要及时完成 | 约 10 s 未完成 → `adapter-error` 占位，审计 `timeout` |
| 宿主调用可能超时 | 单次调用约 15 s 无回应 → 以 `code: 'timeout'` 失败（`HostErrorCode`）。插件应显示可重试的提示，**不要无限自动重试**。需要用户操作的 `requestFileops`、`permissions.request` 不设超时 |
| 错误码 | `HostErrorCode`：`permission-denied` `out-of-scope` `resource-missing` `plugin-unavailable` `invalid-request` `quota-exceeded` `timeout` |

没有 CPU/内存配额：吃满内存的插件最终会被系统或 Chromium 结束，宿主随后按卡死处理。

## 7. 显示方式与“已验证嵌入”

清单字段 `contributes.adapters[].displayMode` **必填**，且必须与来源类型对应（`DISPLAY_MODE_BY_KIND`，安装校验强制，不对应 = 不兼容）。界面用 `displayModeLabel` 显示（授权对话框“显示方式”、插件管理的适配器详情、网页面板外框），完整说明见 `DISPLAY_MODE_FACTS`。

| 来源 | displayMode | 如实名称 | 面板里是什么 | UI 标签（`displayModeLabel`） |
|---|---|---|---|---|
| file | `in-app-reader` | 内嵌渲染 | 适配器在沙箱 iframe 里渲染、宿主绘制的界面节点 | 内嵌渲染 · 应用内阅读（沙箱） |
| web | `in-app-web` | 内嵌网页 | 宿主管理的受限网页面板；工作台菜单/对话框盖住时暂时以**截图占位** | 内嵌网页 · 网页面板 · 仅限 xxx |
| app | `external-managed` | 外部窗口启动 | **状态占位**：程序名、运行状态、启动/切换/关闭按钮、备份摘要；程序画面不在工作台内 | 外部窗口启动 · 程序在自己的窗口中运行，本面板只显示状态占位（不是内嵌窗口） |

没有“内嵌外部窗口”这种 displayMode；见下面“已验证嵌入”。

**为什么不提供通用嵌入**：把别的进程的顶层窗口 `SetParent` 到 Electron 窗口里，Win32 不承诺支持——跨进程父子窗口会合并输入队列（一方卡死另一方也卡死）；DPI 感知模式不一致导致模糊或错位；焦点、输入法、快捷键、拖放、z 序与 WebContentsView 冲突；管理员权限程序（UIPI）和 Store/UWP 程序（ApplicationFrameHost）无法嵌入；很多程序会重建窗口、开多窗口、或自己恢复位置。因此 v1 不提供，P3 也默认关闭。

**逐应用、逐版本验证的嵌入**（`app.embedding`，P3 之后的实验能力）：
1. 适配器在 manifest 中声明 `embedding.verified[]`：程序、产品版本范围、**exe SHA-256**、Windows 版本、DPI 缩放、验证日期/人、证据文件、已知问题；`enabledByDefault` 必须为 false。
2. 用户必须在设置中打开“实验：嵌入已验证的外部程序”，并在该项目上单独开启。
3. 运行时代理比对实际 exe 哈希与 Windows 版本，任一不符 → 自动回落到 external-managed（并提示原因）。
4. 嵌入后标签显示“外部程序（已验证嵌入·实验）”，并保留“弹出为独立窗口”按钮；程序无响应时宿主立即解除父子关系。
5. 验收清单（每个版本都要做）：启动/关闭 20 次无残留；程序卡死时工作台不卡死；100%/125%/150%/200% DPI 与跨显示器拖动；中文输入法候选框位置；Tab/Alt/Ctrl 快捷键归属；最小化/还原/最大化；拖放文件；工作台主题切换；睡眠唤醒。模板中 `embedding.example.json` 只是格式示例。

## 8. 状态与迁移

- 信封 `{v, data}`，`v = stateSchemaVersion`。宿主保存前用 `checkStateForSave` 检查：可序列化、≤ `maxStateBytes`（上限 16 KB）、嵌套 ≤16、无疑似秘密字段名（password/token/cookie/session/apiKey/credential…）、无 >2048 字符的字符串（疑似正文）。不通过 → 保留上一次有效状态并记日志，不打扰用户。
- 恢复：`restoreFromEnvelope` —— 信封非法、`v` 高于当前版本（插件被降级）、`restoreState` 返回 undefined 或抛错 → 默认状态。
- **宿主兜底（修订 5，核心 R4）**：恢复失败时宿主把原信封原样另存为条目的 `state.preserved = {v, data, reason, at, pluginVersion}`，之后插件的每次保存只改 `v/data`，**不会覆盖 `preserved`**；面板上方显示提示条「旧状态已保留，插件新版本无法读取」和按钮「丢弃旧状态」（修订 8）；点“重新加载”换成新版本后仍读不了时同样显示，不会悄悄回到默认视图。已经有保留的旧状态时插件又读不了当前状态，宿主把当前状态作为新的 `preserved`，原来那份挪进 `preserved.earlier`（最多 2 份），都不丢；“丢弃旧状态”一起删除，插件还没保存过新状态的，条目回到默认状态。插件版本变化后（升级/重装）宿主先用 `preserved` 再试一次恢复，成功就提示“插件新版本已恢复之前保留的视图状态”并清掉 `preserved`。插件看不到 `preserved`。这只是兜底：适配器仍应按下一条用 `migrateOrPreserve` 自己保留。
- **网页模板（修订 5）**：网页面板没有插件界面，模板的 `restoreWebState` 在地址不在域内或格式不对时回到首页并把旧状态放进 `legacy`（同 `PreservedLegacyState`），导航时一并保留；核心看到网页条目状态里有 `legacy` 时在面板上方显示“上次保存的网页位置无法恢复，已回到首页；旧状态已原样保留”。
- **升级不丢状态（修订 4）**：迁移在适配器代码中实现，用 `migrateOrPreserve(data, fromVersion, 当前版本, steps, 默认状态)`：迁移成功返回新状态；缺步骤/返回 undefined/抛错 → 返回默认状态 + `preserved`（`PreservedLegacyState`：旧版本号、旧数据原样、原因）。适配器把它存进自己的状态（模板用 `legacy` 字段），一起保存，面板提示“旧版本的视图状态无法迁移，已原样保留（没有丢失）”，可提供“丢弃旧状态”；修好迁移的新版本可以用 `legacy.data/legacy.v` 再试。在 manifest `stateMigrations` 中声明迁移。**不支持向下迁移**。
- 插件停用、文件缺失（插件目录被删）、升级三种情况下，工作区条目都保留：停用 → `adapter-disabled` 占位；缺失/卸载 → `adapter-missing` 占位；条目与状态信封原样留在数据库，重新启用/安装后恢复（核心 e2e：`e2e/e2e-lifecycle.mjs`）。升级时**不自动重载**已打开的面板（产品决定，修订 5）：面板上方显示提示条「插件已更新，点此重新加载」，点击后按新版本重新打开（状态按上面的规则恢复）；权限声明变化需要重新授权时，授权后面板自然按新版本打开。
- 状态属于布局数据：禁用/卸载插件不删除项目状态；主题切换不触碰状态。

## 9. 与核心现有 `api.views.register` 的关系

| 现有视图 API | 适配器 API | 桥接方式 |
|---|---|---|
| `id` | `adapters[].id` | file 适配器即一种视图类型；`viewType = adapterId` |
| `match(resource) → 优先级` | `match.file` + `priority` | 声明式，未激活即可参与“打开方式”；宿主据此计算优先级（需要动态判断的阅读器仍可用内置视图 API） |
| `component` | `open → mount(target)` | 第三方运行在隐藏的沙箱 iframe，不能直接给宿主 React 组件；界面经 postMessage 发送 UiNode，由宿主渲染（核心 `sandboxProtocol.ts`） |
| `serializeState` / `restoreState(raw)` | `getState` / `restoreState(data, fromVersion)` | 适配器版本化；宿主包信封 |
| `setState`（props） | `ctx.requestSave()` | 宿主去抖后拉取 `getState()` |
| 面板参数 `{viewType, resourceId, state}` | `{itemId}` + 项目表 | 布局 schema 4 迁移（§2） |

内置阅读器（builtin.readers）可以继续用视图 API；核心可为每个内置视图自动生成等价的 file 适配器描述，使“项目”模型统一。

## 10. 失败模式与占位

| 占位 kind | 触发 | 标题 / 文案要点 | 操作 |
|---|---|---|---|
| `adapter-missing` | 未安装或已卸载（D3：卸载默认保留条目） | 缺少适配器；项目与状态已保留，安装后自动恢复 | 安装插件、（file）改用默认视图、移除项目 |

| `adapter-error` | activate/open/mount 抛错、iframe 崩溃、档案缺失 | 出错 + 原因；其他面板不受影响 | 重试、（file）改用默认视图、移除 |

| `permission-denied` | 必需权限被拒/撤销、文件不在授权根或扩展名 | 未授予权限 + 权限理由 | 查看权限、移除 |

| `app-not-installed` | 候选 exe 都不存在 | 未找到程序「Notepad++」 | 重试、手动定位（仍须通过签名/哈希校验）、移除 |

| `domain-blocked` | 项目 URL 不在域名内（运行中被拦截的导航只显示横幅，不换占位） | 已阻止访问 + 允许的域名 | 回到首页、用系统浏览器打开（D2：确认后打开） |
| `network-offline` | 页面加载失败 | 无法连接网络 | 重试 |

“改用默认视图”只对本次打开生效，**不改写**项目的 adapterId/state。“移除项目”需确认。

## 12. 安全说明

### 12.1 沙箱视图插件（v1 第三方）
- `<iframe sandbox="allow-scripts" src="kbplugin://<id>/__kb/frame.html">`（不加 `allow-same-origin` → null origin），隐藏，只运行代码；CSP（核心实际值）：`default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src kbfile://plugin data:; font-src 'self' data:; connect-src 'none'`。`img-src` 只放行 `kbfile://plugin`（按插件授权的令牌 URL），不放行 `kbfile://res|root`。
- 与宿主只经 `postMessage` RPC，宿主校验 `event.source` 与消息结构；所有权限检查在宿主侧。
- 插件拿不到 `window.kb`、Node、绝对路径。

### 12.2 webview 加固（P2）
- 推荐由主进程创建 `WebContentsView` 覆盖在面板区域（Electron 不推荐 `<webview>` 标签）；如用 `<webview>`，在 `will-attach-webview` 中强制以下设置并删除任何 preload。
- `webPreferences`：`nodeIntegration:false`、`contextIsolation:true`、`sandbox:true`、`webSecurity:true`、`allowRunningInsecureContent:false`、`experimentalFeatures:false`、无 `enableBlinkFeatures`、`navigateOnDragDrop:false`、无插件 preload；第三方面板禁用 DevTools。
- 会话：`session.fromPartition(宿主派生名)`；`setPermissionRequestHandler`/`setPermissionCheckHandler`/`setDevicePermissionHandler` 全部拒绝（摄像头、麦克风、定位、通知、剪贴板读取、USB/HID/串口、全屏可按需放行）；`webRequest.onBeforeRequest`：主框架按 `domains`，其余请求（子框架、脚本、样式、图片、XHR/fetch、WebSocket、Worker）只放行 https 且主机在 `domains ∪ resourceDomains`（D1），`data:`/`blob:` 不经网络、放行；**不在该分区注册 `kbfile:` 协议**，`file:` 拒绝。
- **资源检查发生在页面自身 CSP 之后**：页面 CSP 已挡掉的请求不会到达 `onBeforeRequest`，所以宿主的“已拦截外部资源”只统计页面放行、但不在声明域名中的请求；声明 `resourceDomains` 时不能以页面 CSP 代替检查，也不能以宿主计数为“页面需要的全部域名”。确定资源域名的方法：查看页面 CSP 响应头与脚本中出现的主机，再在开发者模式下实际浏览确认；只声明内容所必需的（不声明遥测、广告、同意管理脚本），并在 `reason` 中逐个说明用途。`resourceDomains` 会列在授权对话框中，变化后 `declHash` 变化，用户需重新授权。
- 导航：`will-navigate`、`will-redirect`、`will-frame-navigate`（子框架按 `domains ∪ resourceDomains`）都用 `checkNavigation` 校验；资源域名不能用于顶层导航。
- 弹窗：**宿主可以拒绝所有弹窗，包括允许域名内的** `window.open` / `target=_blank`（核心：`setWindowOpenHandler` 一律 `deny`，应用内从不开新窗口）；`popups:'open-external-with-confirm'` 只是在横幅中提供“用系统浏览器打开…”。
- `shell.openExternal` 只由宿主调用，且只对 https、无 userinfo、是该面板最近被拦截的地址或条目 `ref` 本身（主进程再查一次；渲染进程/插件不能借此打开任意地址），二次确认后执行；绝不传 `file:`/`ms-*:`/自定义协议。
- 下载：`will-download` 按 `downloads` 策略取消或询问保存位置（保存后不自动打开）。
- `certificate-error` 不放行；`login`（HTTP 认证）与 `select-client-certificate` 拒绝（v1 无应用内嵌登录）；禁用页面 `window.open` 导致的 `did-create-window`。
- 视图可见性与 z-order：见 §6.3“可见性”。
- 域名匹配用 URL 解析后的 `hostname`，挡住 `developer.mozilla.org.evil.com`、`developer.mozilla.org@evil.com`、端口、http 降级、IDN（统一 punycode）。

### 12.3 进程代理（P3）：不允许任意执行
- 只在主进程执行；适配器只能提交 `{programId, templateId, slots}`。
- exe 解析：环境变量令牌用 Known Folder API（不读可被篡改的进程环境）展开，按顺序取第一个存在者；不做 PATH 搜索、不跟随 `.lnk`、禁止 bat/cmd/ps1/vbs/js 与 `FORBIDDEN_EXE_NAMES`（再按 VERSIONINFO 的 OriginalFilename 复查，防改名）。
- 校验：以共享读、拒绝写的方式打开 exe 句柄 → WinVerifyTrust 签名 + 签名主体比对 / SHA-256 → 版本范围 → 立即启动（缩小 TOCTOU 窗口）；位于用户可写目录（如 `%LOCALAPPDATA%`）的程序必须用哈希而不仅签名者。
- 启动：`spawn(exe, argv, {shell:false, detached:true, stdio:'ignore', windowsVerbatimArguments:false, cwd: exe 所在目录, env: 精简白名单})`；绝不经 `cmd.exe`、绝不 `runas` 提权（需要管理员的程序直接失败）。
- **参数注入防护**（`expandArgs`）：参数是数组；每项是字面量或 `前缀{slot}`；槽位类型化（resource/enum/int），无自由字符串；拒绝双引号、控制字符、换行、尾随反斜杠（MSVCRT 规则下会吞掉收尾引号）、以 `-` 或 `/` 开头的值（防被当成开关）、超长命令行；资源槽位由核心按 resourceId 解析为已注册根内的绝对路径（含 realpath/junction 校验）并检查扩展名。
- 频率限制（每插件 10 秒内最多 5 次）、单实例、只关闭自己启动的进程、用进程句柄跟踪。
- 外部程序对文件的修改不经 fileops；由“启动前自动备份”（D6，§6.4、H12）兜底，可在操作记录中撤销。

### 12.4 状态与存储
- 状态和插件存储都是明文 SQLite；规范禁止存秘密，`checkStateForSave` 做启发式拦截（字段名 + 超长字符串）。
- 网页登录态只存在 Electron 分区里，不进入备份、不进入状态。
- 迁移包（核心“导出迁移包”）**没有加密**，含根目录路径和插件数据；导出界面提示“包里含路径和插件数据，请妥善保管”。只对本机有意义的数据请声明为 `storage.nonMigratableKeys`，导出时排除。

## 13. 版本与兼容
- `ADAPTER_API_VERSION` 独立于应用版本和核心 `HOST_API_VERSION`，semver；0.x 期间次版本可能破坏。manifest 同时声明 `engines.workbench`（核心）与 `engines.adapterApi`。
- 新增权限种类或字段 → 次版本；旧插件遇到未知字段由宿主忽略，未知权限种类则判“不兼容”。
